# GroundWatch 프론트엔드

기존 FastAPI의 정적 화면을 확장한 웹 파드 구현입니다. HTML, CSS, 브라우저 ES 모듈을 사용하며 프론트엔드용 npm 설치·빌드 서버는 필요하지 않습니다. 기존 백엔드와 AI 코드, 공통 계약, Compose 설정은 이 작업에서 변경하지 않았습니다.

## 실행

저장소 루트에서 `docker compose up --build`를 실행합니다. Docker가 실행 중이어야 하며 최초 의존성 다운로드에는 네트워크 연결이 필요합니다.

- 화면: http://localhost:8100/
- 웹 API 문서: http://localhost:8100/api/v1/docs
- 기존 샘플 API 문서: http://localhost:8100/docs
- 종료: `Ctrl+C` 또는 분리 실행 시 `docker compose stop`
- 컨테이너 정리: `docker compose down` (기본 종료에서 볼륨은 삭제하지 않습니다)

기존 모델 초기화와 영속 볼륨은 원래 Compose 절차를 사용합니다. 8077번 UI는 시각적 참고 자료이며 API 호출 대상이 아닙니다.

## 화면과 데이터

- 관측 현황: 관측·예측 깊이, 강수량, 21건 오차와 판정 근거, 자료 최신성, 모델 연결 상태. 20일·60일·사용자 지정 기간과 차트/표 전환.
- 데이터 관리: CSV 등록, 실측/시뮬레이션 구분, 시나리오, 독립 자료/기존 자료 확장, 중복 파일 처리, 버전 선택, 행·열 검증 오류.
- 운영 이력: 과거 구간 분석 접수, 종류별 이력, 실제 단계 이벤트, 상위 분석/재학습 이동, Gate 결과와 실제 모델 적용 여부.
- 모든 요청은 같은 서버의 `/api/v1`로 보냅니다. 업로드 외 변경 요청은 멱등 키를 사용하며, 네트워크 결과가 불확실한 동일 요청은 새로고침 후에도 키를 재사용합니다.
- 목록은 마지막 커서까지 조회합니다. 긴 조회 기간은 API 최대 756일 단위로 나눕니다. 기간·버전 변경 시 이전 요청을 취소하고, 응답 순서가 뒤바뀌어도 이전 자료가 덮어쓰지 못하도록 검사합니다.
- 실행 기록은 접수·진행 상태일 때만 2초 간격으로 갱신합니다. 종료·메뉴 이동·탭 숨김·페이지 종료 시 갱신을 중단합니다. 선택한 자료와 실행은 브라우저 저장소에서 복원합니다.
- 관측 깊이는 지표면에서 아래로 잰 cm입니다. 차트 아래쪽으로 갈수록 깊어집니다. 누락 날짜는 연결하지 않고, 누락값을 0으로 바꾸지 않습니다. 예측선은 모델별로 나누고 모델 버전을 표시합니다.
- 날짜·단위·모델을 차트 툴팁과 표에서 확인할 수 있습니다. 모바일에서 표만 내부 스크롤하며 페이지 전체는 가로로 넘치지 않습니다.

## 현재 한계

기본 HAIC 모델은 지하수 예측 모델이 아닙니다. 실제 서비스에서는 지하수 예측 모델 연결 대기와 비활성화된 실행 버튼이 정상입니다. 지하수 모델 및 양 파드가 합의한 판정 정책이 연결되기 전에는 실제 지하수 예측·자동 재학습 완료를 주장하지 않습니다. 기준 이내 판정도 안전 보장이나 싱크홀 발생 확률을 의미하지 않습니다.

`V1`, `V2` 등은 업로드 순서의 화면용 이름이며 서버의 고유 버전 식별자는 UUID입니다. 예측·판정은 선택 버전의 선행 자료를 포함할 수 있으며 표에 원래 자료 식별자를 함께 표시합니다.

## 파일

- `index.html`: 공통 화면 구조와 메뉴.
- `groundwatch.css`: 기존 다크 팔레트를 확장한 화면 스타일과 반응형 배치.
- `app.mjs`: 페이지 상태, 양식, 데이터 연결, 실행 갱신.
- `client.mjs`: 응답·오류 처리, 페이지 조회, 멱등 키, 날짜·표시 유틸리티.
- `charts.mjs`: 지하수 깊이·강수량 SVG 차트.
- `../../tests/test_frontend.mjs`: 프론트엔드 핵심 로직 검증. 경로는 저장소 루트 `tests/test_frontend.mjs`입니다.
- `../../tests/frontend_fixture.py`: 제품 서버와 분리한 UI 검증용 서버. 경로는 저장소 루트 `tests/frontend_fixture.py`입니다.

## 2026-10-07 검증 기록

- `node --test tests/test_frontend.mjs`: 10개 통과. 커서 조회, 반복 커서 방지, 네트워크 실패·재로드 시 멱등 키 유지, 다른 입력의 키 분리, 취소, 오류 상세, 756일 분할, 누락 날짜, HTML 이스케이프, 종료 상태 구분.
- `docker compose exec -T serving-app python -m unittest discover -s tests -v`: 기존 백엔드·파이프라인 25개 통과.
- 실제 Docker 빌드·재생성 및 서비스 `healthy` 확인. 볼륨의 등록 자료가 재생성 후 유지되는 것을 브라우저에서 확인.
- 실제 8100 UI: 잘못된 CSV 오류 표시, 120일 시뮬레이션 등록, 동일 파일 중복 처리, 125일로 확장, 사용자 지정 기간 125행 전체 표시, 버전 변경·새로고침 복원, 실측 선택 시 시나리오 숨김, 모델 미연결 버튼 비활성화, 키보드 표 전환 확인.
- 데스크톱과 390px 모바일 뷰포트에서 관측·표·데이터 관리 화면 확인. 모바일 페이지 너비 초과 없음. 실제 서비스 브라우저 콘솔 오류 없음.
- 별도 8111 테스트 서버: 빈 상태, 테스트 모델 단일 예측, 비동기 분석 접수·실제 이벤트 표시, 21건 감지 근거, 재학습 연결과 결과, 실행 선택 복원, 실행 중 메뉴 이동, 서버 오류·복구 및 마지막 성공 자료 안내 확인.
- 테스트 서버는 `StubGateway`와 임시 DB를 사용했습니다. 여기에 표시된 예측·RMSE·Gate 결과는 지하수 모델 성능 검증이 아닙니다. 기본 서비스에 가짜 모델이나 고정 응답은 추가하지 않았습니다.
- 실제 로컬 DB에는 검증용 시뮬레이션 파일 `frontend-verification-simulated.csv`(120일)와 `frontend-verification-extended.csv`(125일)가 남아 있습니다. 날짜는 2025-01-01부터이며 실측 자료가 아닙니다.

## 개발 검증 재현

프론트엔드 로직 테스트는 개발용 Node.js가 있을 때 `node --test tests/test_frontend.mjs`로 실행합니다. 서비스 실행에는 Node.js가 필요하지 않습니다.

성공 화면을 개발 중 확인해야 한다면 프로젝트 Python 의존성이 설치된 별도 개발 환경에서 `python3 tests/frontend_fixture.py --port 8111`을 실행할 수 있습니다. 이 서버는 로컬 루프백에만 열고 종료 시 임시 DB를 제거합니다. 공용 실행 절차나 운영 모델로 사용하지 않습니다.
