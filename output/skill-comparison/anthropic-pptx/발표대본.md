# GroundWatch 발표대본

발표자 한형준. 본문 약 14분, 시연 화면 약 3분, 질문 3분. 부록은 질문 대응용입니다.

## 1. GroundWatch

안녕하세요. 광주3반 5조 발표를 맡은 한형준입니다. 저희 팀은 다음 날 지하수위를 예측하고, 예측 오차가 커졌을 때 재학습과 후보 평가까지 이어지는 서비스를 만들었습니다. 오늘은 데이터와 모델, 운영 설계, 실제 실행 증거를 순서대로 말씀드리겠습니다.

## 2. 담당자의 확인 업무

담당자는 여러 관측소를 비교할 때 자료가 언제까지 들어왔는지부터 확인합니다. 모델 오차가 커졌는데도 기존 예측을 계속 참고하는 상황도 피해야 합니다. 서비스 장애는 조회를 막고, 지연은 비교 업무를 어렵게 합니다. 그래서 자료 기준일, 예측 품질, 조치 이력을 분리해서 보여주도록 설계했습니다.

## 3. 공식 과거 관측자료

서울시 공개 관측 화면에서 25개 구의 고정 관측소 자료 52,591행을 확보했습니다. 전체 확보 범위는 2018년부터 2024년 3월까지입니다. 중간 날짜 공백이 없다는 뜻은 아닙니다. 현재 강수는 서울시 화면에 있는 계열이며 기상청 ASOS API와 새로 결합한 자료는 아닙니다.

## 4. 20일 입력, 다음 날 수위

한 관측소의 연속 20일 수위와 강수가 입력이고 바로 다음 달력 날짜의 수위가 정답입니다. 입력 모양은 20 곱하기 2입니다. 미래 강수를 사용하지 않으며 날짜가 빠진 구간을 서로 이어 붙이지 않습니다. 정답이 아직 공급되지 않았을 때는 평가를 계산하지 않습니다.

근거: team/data/groundwater.py; team/docs/team-logic-guide.md

## 5. 같은 날짜, 같은 관측소

HTML의 날짜, 수위, 강수 배열에서 같은 인덱스를 읽었습니다. 요청한 station ID를 고정 manifest에 연결합니다. 수위의 원천 부호는 보존하고 같은 관측소·날짜의 값이 충돌하면 제외했습니다. 빈 강수를 0으로 채우거나 날짜를 보간하지 않았습니다.

근거: team/scripts/import_official_groundwater.py; team/data/groundwater.py

## 6. 시간을 따라 나눈 평가

무작위 분할 대신 정답 날짜순으로 나눴습니다. 최대 730개 유효 학습 표본, 검증 60개, 테스트 60개, 재생 90일입니다. 각 표본 안의 날짜는 연속이어야 합니다. scaler의 최소·최대도 학습 자료로만 맞췄습니다. 다만 개발 중 테스트 결과를 확인했으므로 이를 독립 외부 평가라고 말하지 않습니다.

근거: team/data/representatives.json; team/evidence/frozen-data-manifest.json

## 7. 마지막 수위와 학습한 변화량

잔차 LSTM은 마지막 관측 수위에 학습한 변화량을 더합니다. 관측소별로 독립 모델을 관리하고 역변환해 gl.-m로 응답합니다. 비교 기준인 persistence는 마지막 수위를 그대로 예측합니다. 수위가 거의 변하지 않는 구간에서는 이 단순 기준도 강하기 때문에 복잡한 모델이 항상 우수하다고 가정하지 않았습니다.

근거: team/serving_app/groundwater_models.py

## 8. 시간 분리 평가 결과

RMSE는 sqrt(mean((예측-정답)^2))로 계산하며 수위 단위 gl.-m를 따릅니다. 낮을수록 평가 자료에서 오차가 작으며 큰 오차에 더 민감합니다. 가이드의 WAPE는 판매량처럼 실제 규모가 의미 있는 비음수 값에서 비교하기 좋지만, 현재 gl.-m 수위는 음수이고 기준면 offset에 의존하므로 실제값 합을 분모로 쓰는 WAPE를 그대로 적용하지 않았습니다. 동일 시간 분할에서 persistence와 비교한 관측소별 RMSE를 평균한 macro RMSE입니다. 잔차 LSTM의 검증 RMSE는 0.265764, 테스트는 0.182625이고 persistence는 각각 0.304802와 0.208106입니다. 현재 내부 분리 자료에서 확인한 결과이며 현장 위험 예측이나 독립 외부 일반화 성능으로 확대하지 않습니다.

근거: team/evidence/README.md; team/proposal.md

## 10. 학습부터 운영까지

## 11. 운영 목표와 로컬 실측

운영 목표 초안은 준비된 전체 조회 p95 1초 이하와 통제된 100회 정상 요청에서 5xx 1% 미만입니다. 로컬 warm 순차 요청은 100회 모두 200이었고 p95 0.0404초였습니다. cold 최초는 3.849초였습니다. 최근 300초 요청을 60초마다 보되 최소 20건 전에는 판단을 보류합니다. 목표 초과 시 운영 담당자가 자료 신선도와 worker, 모델 로딩 및 로그를 확인합니다.

근거: team/evidence/README.md; team/docs/contracts.md

## 12. 감지에서 후보 검증까지

초기 모델은 검증 RMSE가 persistence의 110% 이내인지 확인합니다. 배포 후에는 21일 RMSE가 초기 검증 60일 구간의 21일 rolling RMSE P95의 1.5배를 연속 두 번 넘으면 후보 작업을 만듭니다. 후보는 최근 41일로 학습하고 후속 30일 정답에서 기존 모델보다 5% 개선되어야 합니다. 과거 guard 110%와 로드 검사도 통과해야 교체합니다. 이 정책은 일시 오차와 잦은 교체를 줄이려는 과제 운영 가설이며 재난 기준이 아닙니다. 입력분포 변화(data drift)와 입력-정답 관계 변화(concept drift)는 다릅니다. 현재는 RMSE 오차 경보를 관찰한 것이며 원인을 통계적으로 구분해 확정하지 않았습니다.

근거: team/docs/contracts.md; team/scripts/analyze_monitor_policy.py

## 13. 오늘 기준 합성 확장

기존 관측값을 그대로 보존하고 마지막 실측 다음 날부터 서울 오늘까지 합성 일별 자료를 추가하는 방식으로 바꿨습니다. 과거 월별 수위·강수 쌍을 고정 seed로 재표본화하고 마지막 실측 앵커에서 완만하게 연결합니다. 기존 날짜 공백은 채우지 않습니다. 별도 합성 데이터셋과 모델 namespace에서 시간순으로 학습하고 오늘까지의 연속 20일로 내일 수위를 예측하도록 구성합니다. 최신 API 관측을 확보했다는 뜻은 아니며 최근 구간이 합성이므로 지표도 현장 성능이 아닙니다. 전체 25개 별도 합성 모델의 학습 작업 완료와 오늘 10월 8일 입력, 내일 9일 예측을 실제 HTTP로 확인했습니다. 기존 실측 모델의 25개 준비 상태도 보존했습니다.

근거: team/docs/current-extension-design.md; team/evidence/current-extension-http.json

## 14. 01 전체 현황

최신 전체 현황 화면입니다. 별도로 학습한 합성 확장 모델 25개가 준비되었고 입력 기준일은 오늘 10월 8일, 예측 대상일은 9일입니다. 화면에서 합성 확장 자료임을 표시하며 실제 최신 서울 관측이라고 설명하지 않습니다. 캡처는 안내 배너를 짧게 바꾸기 전 저장한 원본입니다. 현재 화면은 짧은 합성 출처 안내를 표시하고, 생성 방법과 기간은 안내의 상세 설명과 팀 문서에서 확인합니다. 기본 모드는 오늘 기준 예측이며 과거 관측 검증은 별도 모드입니다. 원본 캡처는 수정하지 않았습니다.

근거: team/evidence/current-extension-overview.png; team/evidence/current-extension-http.json

## 15. 02 관측소 상세

종로 관측소 상세입니다. 최종 화면의 모델 버전 2가 10월 8일까지의 합성 확장 입력으로 9일 수위를 예측했습니다. 내일 정답은 아직 없으므로 관측과 강수를 null로 표시합니다. 선 그래프는 합성 확장 구간을 포함하며 현장 성능의 근거가 아닙니다.

근거: team/evidence/current-extension-detail.png; team/evidence/current-extension-http.json

## 16. 03 모델 품질 운영

전체 현황과 관측소 상세를 확인한 뒤 모델 품질 운영으로 이동합니다. 자료 검증, 오차 감시, 품질 경보, 재학습, 후보 평가, 모델 교체, 현재 모델 서빙의 7단계를 확인합니다. 현재 자료 검증과 모델 v2 서빙은 완료되어 있고 정답 미도착으로 오차 감시부터 후보 교체까지 대기 상태임을 구분합니다. 작업과 이벤트를 함께 확인하고 문제가 생기면 기존 모델 유지와 복귀 이력을 확인합니다. 오늘 기준 자료는 기존 공식 원관측을 보존한 별도 합성 확장이며 최신 실시간 API 관측이 아닙니다. 수동 CSV와 manifest 등록, 초기 학습 및 과거 자료 재생은 접힌 내부 관리 기능으로 보존하고 주 시연 동선에서는 제외합니다. 현재 화면의 과거 자료 모드 명칭은 과거 관측 검증입니다. 초기 자료 준비는 서버 기동 시 자동으로 수행되며 사용자의 CSV 입력이 기본 예측의 필수 단계는 아닙니다.

## 24. 부록 합성 확장 모델의 내부 평가

오늘까지 확장한 별도 합성 모델 25개의 지표를 평균한 결과입니다. 검증 macro RMSE 0.016396, 테스트 0.020471이며 persistence는 각각 0.016561과 0.020544입니다. 같은 시간 분할에서 비교했고 최근 최대 730개 학습 표본, 검증 60일, 테스트 60일, 재생 90일로 나눴습니다. 검증은 2026년 3월 13일부터 5월 11일, 테스트는 5월 12일부터 7월 10일입니다. 합성 생성식이 완만한 자료를 만들기 때문에 이 작은 오차를 기존 실측 모델의 테스트 RMSE 0.182625와 직접 비교하면 안 됩니다. 실제 서울 최신 관측이나 현장 예측 성능이 아닙니다.
