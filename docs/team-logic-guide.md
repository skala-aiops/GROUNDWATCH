# GroundWatch 교수님 원본과 현재 로직 비교

팀원이 처음 사용할 때는 [대상 사용자와 화면 사용법](../demo.md)을 먼저 읽어주세요. 업무 담당자의 조회와 운영자의 자동 재학습 시연을 구분합니다.

## 2026-10-08 최신 변경

사용자 요청으로 기본 시연을 실제 달력의 오늘 입력→내일 예측으로 변경했습니다. 공식 과거 52,591행을 보존하고 2024-03-19부터 서울 오늘까지 합성 수위·강수량을 붙여 별도 자료·모델로 학습합니다. 2026-10-08 기준 합성 23,350행, 총 75,941행입니다. 원관측 값의 날짜만 옮기지 않으며 기존 공급 시뮬레이션의 API·기록은 보존하며 중복 시작 버튼은 현재 화면에서 제외합니다.

강수는 관측소별 과거 같은 달의 값에서 고정 seed로 재표본화합니다. 수위는 직전 값에서 과거 같은 달 중앙값을 향해 3% 이동하고 같은 달 표본의 중앙값 대비 편차를 1.5% 더합니다. 물리적 지하수 모델이나 기상청 최신 강수를 대신하지 않습니다. 최근 730개 학습 target은 대부분 합성이며 별도 검증·테스트 지표도 합성 시연의 품질만 설명합니다. 원본 모델의 과거 실측 지표는 유지합니다.

CSV 행마다 observed/synthetic 출처를 유지하고 전체 자료는 synthetic namespace로 격리합니다. 화면은 짧은 ‘시연 데이터 · 합성 자료 포함’ 표시를 제공하고, 원관측 종료일·합성 기간·생성 방법은 상세 설명과 문서에서 확인합니다. 구현·누수 방지·검증 기준은 `current-extension-design.md`, 실제 실행 결과는 `../evidence/README.md`를 확인합니다. 아래에서는 기본 오늘 예측, 저장 자료 검증, 보류한 외부 API 경로를 구분합니다. 날짜를 옮기는 공급 재생 설명은 화면에서 제외한 이전 API·기록에만 적용됩니다.

## 팀이 알아야 할 확정 범위

2026-10-07 사용자 전달: 교수님께서 시뮬레이션 데이터를 만들어 과제를 진행해도 된다고 허용하셨습니다. 이번 결과물은 실제 납품·판매 완료품이 아닌 과제용 서비스 시제품입니다. 이 허용은 데이터 시뮬레이션에 관한 것이며 B2B/B2G 주제 인정이나 제출 완료까지 확인된 뜻은 아닙니다.

기본 오늘 예측은 공식 과거 관측과 이후 생성한 합성 일별 자료를 함께 사용합니다. 반면 보존한 **과거 공급 재생 도구**는 확보한 서울 공식 과거 관측값만 사용합니다. 이를 하루씩 들어오는 자료처럼 공급하고 별도 시연 시계를 오늘에서 시작합니다. 원관측일·값·단위는 그대로 보존합니다. 예를 들어 시연10월7일에 과거12월19일까지의20일 입력으로 과거12월20일 수위를 예측하고, 이를 시연10월8일 예측으로 표시합니다. 하루 공급 후에만 그 정답을 공개합니다.

| 부분 | 현재 실제 동작 |
| --- | --- |
| 기본 자료 준비 | 기동 시 공식 과거 자료를 보존하고 오늘까지 합성 확장·별도 학습 |
| 과거 공급 재생 | 공식 관측을 하루씩 공개하는 내부 운영 실험 |
| 학습·추론 | 실제 잔차 LSTM·scaler·TensorFlow 예측 |
| 운영 루프 | 실제 예측 저장·정답 대조·오차 감시·재학습 작업·후보 평가·교체 또는 기존 유지 |
| 날짜 | 기본은 실제 달력의 오늘→내일, 과거 공급 재생만 원관측·표시 달력 분리 |
| 외부 API | 조사·실패 증거와 코드는 보존, 최신 실측 연결은 미완료 |
| 성능 해석 | 공식 과거 실측 평가와 합성 확장 평가를 구분하며 최신 현장 성능은 미검증 |

정상 공식 자료의 시연에서 후보가 반드시 승격하는 것은 아닙니다. 서울 과거 재생의 거절·정답 대기와 별도 합성 자료의 자동 승격 성공은 구분합니다. 수위 변화 모의 시나리오와 날짜만 순차 공급하는 시뮬레이션도 서로 다릅니다.

기본 화면은 오늘 기준 예측과 자료 출처를 안내합니다. 현재 시연은 ‘모델 관리 · 시연’의 기본 상황·수위 변화 시연으로 시작하고 저장 자료를 1일·21일 진행합니다. 이전 공급 재생의 중복 시작 도구는 화면에서 제외했으며 기존 API·기록은 보존합니다. 원관측일은 표·상세·API에 보존합니다. 팀은 발표에서 ‘오늘 기준 예측에는 과거 관측에 합성 자료를 추가했고, 학습·예측과 운영 로직은 실제 실행한다’고 설명합니다. 화면의 ‘저장 자료로 검증’은 선택한 실측 또는 합성 자료를 순차 공개하는 실험이며, ‘검증 기록 선택’은 해당 시연의 모델·진행 날짜·결과를 고르는 기능입니다.


팀원이 전체 흐름과 변경 이유를 이해하기 위한 설명입니다. 현재 설명의 기준일은 2026년 10월 8일입니다. 10월 7일 실험은 해당 날짜의 증거로 구분합니다. 원본은 `../../individual/practice/project/`, 팀 작업본은 `../`입니다. 제공 코드·팀 도메인 변경·AI를 통해 추가된 구현을 특정 팀원의 개인 작성 성과로 동일시하지 않습니다.

## 먼저 이해할 핵심

교수님 예제는 주가 데이터로 **입력 → 학습 → 예측 → 오차 감지 → 재학습 → 운영 모델 교체**를 배우는 구조입니다. 우리 프로젝트는 이 운영 루프를 지하수 관측자료로 바꾸고, 여러 관측소·실제 외부 자료·검증·이력 관리까지 추가했습니다.

현재 기본 화면은 **오늘 기준 합성 확장 경로**를 사용합니다. 기동 시 공식 원관측 이후부터 서울 오늘까지 별도 자료를 생성하고, 검증·학습된 해당 자료의 모델로 오늘까지 입력→내일 수위를 예측합니다. CSV 수동 등록은 기본 필수 절차가 아니라 운영의 접힌 관리 도구입니다. **과거 재생 경로**는 정답을 순차 공개하며 오차 감시·재학습을 검증하는 내부 실험이고, **외부 실측 API 경로**는 최신 원천 의미·단위·매핑이 미검증이어서 보류했습니다. 내부 API의 `mode=current`는 기본 오늘 예측을 뜻하며 보류한 외부 `/live` 경로와 같지 않습니다. 인증키 설정만으로 외부 실측 예측이 준비되지는 않습니다.

현재 모델이 하는 일은 관측소의 수위를 예측하는 것입니다. 싱크홀 확률, 구 전체 안전도, 현장 점검 순위를 계산하는 모델은 아닙니다. 모델 오차가 커지면 예측 모델을 확인해야 한다는 뜻이지 해당 현장이 위험하다는 뜻은 아닙니다.

## 전체 구성과 각 파일의 책임

```text
기동: start_container.py → current_extension.py → 별도 자료 검증·학습
현재 화면 index.html + groundwatch.js (외부 수집 화면 미노출)
                    ↓ HTTP 요청
main.py → groundwater_api.py
                    ↓ 업무 요청
groundwater_service.py ── groundwater_store.py
       ↓                         작업·이벤트·상태 저장
groundwater_models.py ← groundwater_worker.py
       ↓                         오래 걸리는 작업 실행
TensorFlow + MLflow + 모델·scaler 파일

서울시·기상청 API
       ↓ external_observations.py ← external_worker.py
원본 수집·검증 → observation_repository.py
       ↓ 관측 수정 이력·매핑·고정 입력 자료
live_observations.py → 기존 모델 관리·작업 실행과 연결
       ↓
보류한 외부 실측 예측·정답 비교 경로 (기본 화면 자료 공급 아님)
```

| 파일 | 팀원이 이해할 책임 |
| --- | --- |
| `data/current_extension.py` | 원관측 보존·오늘까지 합성 생성·출처와 별도 manifest 기록 |
| `scripts/start_container.py` | 기동 시 자료 준비·최초 학습 접수와 worker/API 시작 |
| `data/groundwater.py` | 정규 자료 형태, 관측소·날짜·값 검증 |
| `groundwater_api.py` | 요청을 검사하고 조회 결과나 작업 ID를 반환 |
| `groundwater_service.py` | 과거 자료·재생·작업·감시 흐름을 연결 |
| `groundwater_models.py` | 학습, scaler, 예측, 모델 평가·등록·교체·복귀 |
| `groundwater_store.py` | 작업·이벤트 등 상태를 영속 저장 |
| `groundwater_worker.py` | 접수된 학습·예측·재생 등 작업 실행 |
| `external_observations.py` | 서버 인증키로 API 수집, 재시도, 오류 자료 격리 |
| `external_worker.py` | 외부 자료 수집 작업과 일별 주기 실행 |
| `observation_repository.py` | 수집 이력·관측 수정본·매핑·스냅샷·예측·평가 저장 |
| `live_observations.py` | 현재 자료 준비도 확인, API 자료 학습·예측·오차 평가 |
| `static/` | 결과 표시와 요청. 학습 자체를 브라우저에서 실행하지 않음 |

worker는 API 요청이 끝난 뒤에도 오래 걸리는 작업을 수행하는 프로세스입니다. namespace는 과거·모의·현재 실험의 모델과 상태를 서로 다른 칸에 보관하는 구분자입니다. snapshot은 예측에 사용한 관측자료를 나중에도 똑같이 확인할 수 있도록 고정한 묶음입니다. champion은 현재 예측에 사용할 모델 버전을 가리키는 이름입니다.

## 기본 오늘 예측을 한 번 따라가기

1. 기동 스크립트가 공식 원본을 읽고 오늘까지의 별도 확장 CSV·manifest를 만듭니다. 과거 원본의 공백·값·날짜는 바꾸지 않습니다.
2. 동일 자료가 없으면 검증·초기 학습을 worker 작업으로 접수합니다. 이미 준비된 동일 날짜 자료·모델은 재사용합니다.
3. 관측소별 시간순 train/validation/test/replay 분리와 train-only scaler로 별도 LSTM을 학습하고 초기 게이트를 확인합니다.
4. 화면은 `GET /api/v1/forecasts?mode=current`로 오늘까지 연속 20일을 입력한 내일 예측과 모델 버전을 조회합니다. 내일 정답·강수는 아직 없으므로 null입니다.
5. 운영 화면은 현재 모델·작업·이벤트와 정답 도착 후 감시 상태를 구분합니다. 오늘 예측 한 번만으로 21일 정답 감시나 자동 승격이 완료된 것으로 표시하지 않습니다.

화면 상세는 상단 예측 카드에 대상일·수위·마지막 입력과의 차이를 표시하고, 최근 30일을 기본으로 90일·180일 수위·강수 그래프를 제공합니다. 자료·모델 정보는 접어 두었습니다. 시연 초기화 중에는 예측을 조회하지 않으며, 준비 완료 시 자동으로 갱신합니다. 자료 진행 중에는 실제 작업의 대기·실행·완료 일수와 실패·중단을 표시합니다. 화면의 모델 복귀는 사유 입력 없이 요청하고 API에는 고정 사유를 남깁니다.

## 수동 CSV 등록과 과거 재생을 한 번 따라가기

1. CSV와 관측소 manifest를 등록합니다. manifest는 각 관측소의 ID·구 코드·단위·매핑 버전을 설명하는 설정입니다. 파일을 받았다는 응답과 자료 검증 완료는 다릅니다.
2. 날짜·관측소·단위·값을 검증합니다. 강수량 결측을 0으로 바꾸지 않고, 충돌하는 자료를 격리합니다. 유효한 연속 날짜에서만 입력과 정답을 만듭니다.
3. 관측소별 과거 자료를 학습·검증·시험 기간으로 나눕니다. 미래 정답이 학습에 들어가면 과거 실력이 실제보다 좋아 보이므로 시간 순서를 지킵니다. scaler도 학습 자료로만 맞춥니다.
4. worker가 학습하고 평가합니다. 모델은 마지막 관측을 그대로 다음 날 예측하는 단순 기준과 비교합니다. 등록됐다는 사실과 실제 운영 모델로 선택됐다는 사실을 구분합니다.
5. 예측할 때 직전 20일 자료와 일치하는 모델·scaler를 불러옵니다. 출력은 그 관측소의 다음 날짜 수위입니다.
6. 과거 재생에서는 기준일을 하루씩 진행합니다. 그날까지 알 수 있는 자료만 사용하며 정상 재생과 모의 수위 변화 재생은 따로 저장합니다.
7. 정답이 생기면 저장 예측과 비교해 오차를 계산합니다. 오차 증가 조건에 해당하면 이벤트와 재학습 작업을 만듭니다.
8. 재학습 모델은 우선 후보입니다. 평가 조건을 통과해야 운영 모델을 교체합니다. 실패·반려되면 기존 모델을 유지하며 필요하면 이전 검증 모델로 복귀합니다.

RMSE는 예측과 실제 관측의 차이를 하나의 수치로 요약한 값입니다. 작을수록 해당 평가 자료에서 오차가 작습니다. 수위 측정 기준과 단위가 다르면 같은 숫자를 바로 비교할 수 없습니다.

## 보류한 API 경로의 설계 이해

1. 서버 `.env`의 인증키로 서울시 지하수 자료와 기상청 ASOS 일자료를 요청합니다. 브라우저에 키를 전달하지 않습니다.
2. 원본과 수집 결과를 남기고 날짜·수치·결측 등을 검사합니다. 오류 자료는 예측 입력에서 제외하되 실패 이유를 남깁니다.
3. 서울시 관측소, 과거 관측소, ASOS 지점이 어떻게 연결되는지 검증합니다. 이름이 비슷하다는 이유만으로 동일 관측소로 승인하지 않습니다. 수위 단위·측정 기준도 확인해야 합니다.
4. 승인된 매핑으로 수위와 강수량을 날짜별로 연결합니다. 수집 시점까지 알 수 있었던 자료를 사용하고, 이후 수정본이 생겨도 이전 예측 근거를 덮어쓰지 않습니다.
5. 예측 입력을 고정 스냅샷으로 만듭니다. 현재 일별 예측에는 전일까지 연속 20일 자료가 필요합니다. 부족하면 예측을 만들지 않고 부족 상태를 반환합니다.
6. 같은 관측소·단위·매핑·특징 계약에 맞는 모델이 있는지 확인합니다. 과거 CSV 모델을 API 자료에 자동 적용하지 않습니다. API 자료 학습 경로는 `observed_api_v1`로 분리됩니다.
7. 예측 작업을 실행하고 입력 스냅샷·모델 버전·발행 시각·대상 날짜와 결과를 저장합니다.
8. 실제 정답 관측이 나중에 수집되면 당시 저장 예측과 비교합니다. 정답 지연을 0이나 성공으로 취급하지 않습니다. 평가·재학습·교체는 이 실제 가용 시점을 따라갑니다.

보류한 외부 실측 경로의 예를 들면 10월 7일 예측은 9월 17일~10월 6일의 연속 20일 자료로 10월 7일 수위를 구하는 구조입니다. 10월 7일 강수량을 미리 아는 것으로 가정하지 않습니다. 이 경로의 입력으로 10월 8일까지 예측한다고 설명하면 계약과 다릅니다. 기본 합성 확장은 10월 7일까지 입력으로 10월 8일을 예측하는 별도 경로입니다.

서울시 API와 기상청 API는 인증 응답을 확인했지만, 현재 서울시 자료의 식별·단위·조회 동작과 관측소 매핑 검증이 남았습니다. 따라서 현재 API 경로에서 25개 예측을 실제로 발행하고 있다고 설명하면 안 됩니다. 과거 자료의 실행 결과와 API 경로의 준비 상태는 각각 확인해야 합니다.

## 저장소가 늘어난 이유

| 저장 대상 | 필요한 이유 |
| --- | --- |
| 원본·검증 결과 | API가 준 값과 제외 이유를 확인 |
| 매핑 버전 | 어떤 관측소·기상 지점을 연결했는지 확인 |
| 관측 수정 이력 | 원천이 나중에 수정한 값과 당시 알던 값을 구분 |
| 스냅샷 | 특정 예측의 실제 입력을 재현 |
| 모델·scaler·MLflow 버전 | 어떤 모델과 전처리로 예측했는지 확인 |
| 작업 상태 | 접수·진행·실패·완료와 재시도를 구분 |
| 예측·평가 | 나중에 들어온 정답과 당시 예측을 비교 |
| 이벤트·교체 이력 | 왜 확인·재학습·교체·복귀했는지 추적 |

그래서 화면에 revision·hash·namespace를 모두 노출할 필요는 없어도 이력을 저장하는 로직까지 불필요한 것은 아닙니다. 반대로 현재 이벤트에는 기관 사용자별 책임 추적과 권한이 충분히 구현되지 않아, 저장 기록이 있다는 이유만으로 기관 감사 요건을 충족한다고 설명할 수 없습니다.

## 팀 설명과 구현 순서

팀 설명은 먼저 교수님 원본의 운영 루프를 보고, 아래 데이터 설명에서 관측소 하나의 원본·입력·정답·예측을 따라갑니다. 다음으로 기본 오늘 예측의 합성 생성·시간 분리·출처 경계를 확인하고, 현재 시연의 저장 자료 진행과 정답 공개 순서를 봅니다. 별도 표시 달력을 쓰는 이전 공급 재생은 보존한 API·기록 설명으로만 읽습니다. 이어서 재학습 후보가 실제 운영 모델이 되는 조건을 확인합니다. 보류한 API 경로는 후속 확장 설명으로 구분합니다.

프론트 담당자는 자료 상태·예측 상태·모델 평가·업무 확인을 섞지 않는 표시를 먼저 확인합니다. 데이터 담당자는 관측소 식별·단위·연속 날짜·원천 수정 조건을 확인합니다. 모델 담당자는 시간 분리·기준 모델·scaler·후보 평가를 확인합니다. 운영 담당자는 작업 실패·재시도·모델 교체·복귀 후 실제 예측 버전을 확인합니다. 이는 역할별 검토 제안이며 실제 팀원 기여를 확정하는 기록은 아닙니다.

화면과 기능의 유지·이동·제거 계획은 [공공기관 서비스 검토](public-agency-service-review.md)에 있습니다. 현재 화면은 업무 조회와 모델 관리·시연을 구분하고, 관리자 자료 관리를 접어 표시합니다. 교수님 원본, 확보 자료, 기존 모델과 실행 증거를 삭제하는 계획은 없습니다.

## 상세 이력 연결 보완

보류한 외부 API 상세 경로도 승인된 자료와 같은 특징 계약의 저장 예측·모델 교체 이력을 반환합니다. 아직 정답이 없는 날짜는 관측값을 null로 남기고 예측만 표시합니다. 실패한 수집의 수정값과 다른 계약의 예측을 이력에 섞지 않습니다. 차트의 날짜별 자료는 접힌 표로도 확인할 수 있습니다. 원천 대조 결과는 evidence/api-unit-crosscheck.json에 있으며 실제 현재 API 예측 활성화 근거는 아닙니다.

## 최종 기획과 원래 사업기획의 차이

원래 사업기획은 관측소 하나의 가상756일 자료, 수심cm·강수×10 정수 입력을 제안했습니다. 현재는 서울25개 고정 관측소의 공식 과거52,591행과 오늘까지 별도로 생성한 합성 확장 자료, 원천 부호를 보존한gl.-m·강수mm 실수 입력을 사용합니다. 20일 입력→다음 날 수위라는 문제는 유지하되 관측소별 학습·버전·정답·오차를 격리합니다. 입력 단위와 모델이 바뀌었으므로 원래 스케일러·가중치를 그대로 재사용하지 않습니다.

기존 drift→fine-tuning→gate 흐름에는 영속 작업, persistence 비교, 후속30일 후보 평가, 실제champion/캐시 교체·실패 시 기존 유지·롤백을 추가했습니다. 현장 점검 우선순위·사고 확률은 구현한 모델의 출력이 아닙니다. 과거 날짜의 정답을 순차 공개하는 실험과 오늘 실측 운영도 구분합니다. API·GIMS 전환은 보류했고 현재 화면에서 제거했습니다.

## 보존한 과거 공급 재생 도구

화면에서 제외한 이전 공급 재생의 ‘새 시뮬레이션 시작’ 동작은 POST /api/v1/replays에 presentation_start_date를 추가하며 historical 시나리오만 사용합니다. GET /forecasts와 /pipeline의 simulation 객체는 원관측 source_as_of/source_forecast_date와 표시용 presentation_as_of/presentation_forecast_date를 구분합니다. 실제 date/as_of/forecast_date는 그대로이며 예측 행의 presentation_observed_date/presentation_forecast_date, history의 presentation_date만 추가합니다. source_kind=observed는 값의 실제 출처이고 시연 날짜의 실측이라는 뜻은 아닙니다.

새 namespace에서 초기 검증 모델을 복사하거나 기존 초기 학습을 실행하고25개 준비 후 하루씩 진행합니다. /replays/{id}/advance의 days는 시뮬레이션에서1만 허용합니다. 진행은 기존 worker가 예측 저장→정답 공개→오차 감시·필요시 재학습 순으로 수행합니다. 다음 날 예측만 있는 history 행은 관측·강수 null입니다. SQLite의 세션 시작일을 보존하므로 새로고침·재시작에도 시연 시계가 유지됩니다. 설계는 [공급 시뮬레이션 설계](supply-simulation-design.md), 실제 결과는 [HTTP 검증](../evidence/supply-simulation-http.json)을 따릅니다.

## 데이터가 모델과 화면까지 연결되는 과정

### 1. 어떤 자료를 사용했는가

기본 자료 중 원관측 구간의 수위와 강수는 모두 서울특별시 물순환정보 공개시스템의 관측자료 화면에서 확보했습니다. 서울 열린데이터광장은 자료 안내 출처이고, 원관측 값을 가져온 경로는 관측소별 공개 HTML이며 이후 날짜는 합성 생성 경로를 거칩니다. 조회일은2026-10-07, 확보한 관측 기간은2018-01-01~2024-03-18입니다. 공개 사이트가 존재한다는 것과 최신 관측값을 확보했다는 것은 다릅니다.

서울시 지하수 API와 기상청 ASOS API는 인증·수집을 조사했지만 현재 학습·예측 CSV에 결합하지 않았습니다. 원관측 rainfall_mm을 ‘기상청 API를 붙인 값’이라고 설명하면 안 됩니다. 원관측 구간은 서울시 화면이 제공한 강수이며 합성 구간은 같은 달 표본에서 재표본화한 값입니다. 그 강수의 원래 기상 관측소 코드는 독립 확인되지 않았습니다. GIMS도 신청 오류로 접수 미확인 상태여서 사용하지 않았습니다.

### 2. 원본 수위와 강수를 어떻게 엮었는가

관측소 코드를 지정해 받은 HTML의 날짜 배열 categories1, 수위 seriesData1, 강수 seriesData4에서 같은 배열 인덱스를 읽었습니다. 외부 JavaScript를 실행한 것이 아니라 값의 대입문을 추출했습니다. 같은 인덱스의 날짜·수위·강수를 한 관측 행으로 묶고, 요청에 사용한 관측소ID와 구 코드를 붙였습니다. 현재 데이터는 서로 다른 두 API를 날짜만으로 합친 결과가 아닙니다.

관측소 이름만으로 합치면 동명이름·이름 변경을 구분하기 어려우므로 station_id를 기준으로 고정 manifest를 연결합니다. 같은 구의 여러 관측소를 평균하거나 다른 관측소의 빈 날짜로 대체하지 않습니다. 대표는 각 구 한 곳이며 관측소 식별과 자료 범위를 보고 고정했고 모델 성능 순위로 골라 바꾸지 않았습니다. 구 코드는 목록·선택·모델을 연결하는 식별자이고, 예측 대상은 그 구 전체 평균이 아닌 해당 관측소입니다.

정규 행의 열은 station_id, district_code, date, groundwater_level, rainfall_mm, level_unit입니다. 원천 수위 표기 gl.-m과 음수 부호를 보존하고 강수는mm 실수로 씁니다. cm 변환·절댓값·강수×10 정수 변환을 하지 않았습니다. 같은 station_id/date에 같은 값이 반복되면 하나로 정리하고, 값이 충돌하면 그 날짜를 제외합니다. 비수치·무한값·미래 관측일·음수 강수·결측은 검증에서 제외하며 빈 강수나 빈 날짜를0·보간으로 채우지 않습니다. 원본 HTML·요청URL·해시는 runtime/official/sources와 evidence/official-data-coverage.json에 보존했습니다.

### 3. 입력20일과 정답1일을 어떻게 만드는가

한 관측소의 행을 날짜순으로 정렬하고, 연속20일의 [수위, 강수]를 입력X로 만듭니다. 바로 다음 달력 날짜의 수위 하나가 정답y입니다. 한 표본의 입력 모양은(20,2), 모델에 한 건을 보낼 때는(1,20,2)입니다. 다음 날 강수나 다른 구의 수위는 넣지 않습니다. 20일 입력 중 날짜가 빠지거나 다음 날 정답이 없으면 해당 학습 표본을 만들지 않습니다.

예를 들어 종로구 원관측2023-11-30~12-19의20일 입력으로12-20 수위를 예측합니다. 시연 시계의 첫날을2026-10-07로 설정하면 같은 예측을 ‘시연10월8일’로 표시하지만 원관측일과 수치 자체는 바꾸지 않습니다. 모델이 아직 보지 않은 다음 날 정답은 하루 공급을 눌렀을 때만 평가 경로에 공개합니다.

### 4. 학습·검증·테스트·시연은 어떻게 나눴는가

기본 합성 확장도 최근 최대730개 train target·검증60일·테스트60일·재생90일의 같은 규칙을 씁니다. 2026-10-08 확장 자료의 train 정답은2024-03-13~2026-03-12, 검증2026-03-13~05-11, 테스트2026-05-12~07-10, 재생2026-07-11~10-08입니다. 최근 학습 대부분과 검증·테스트는 합성입니다. 아래 날짜 예시는 보존한 **원관측 전용 과거 실험**이며 기본 확장 모델의 분할 날짜가 아닙니다.

무작위 분할이 아니라 정답 날짜순으로 나눕니다. 공통 재생 정답은2023-12-20~2024-03-18의90일입니다. 그 이전 연속60개 정답은 테스트, 그 이전60개는 검증, 그보다 과거의 유효 표본 중 최근 최대730개는 학습입니다. 결측 때문에730표본이730개 연속 달력 날짜를 뜻하지 않습니다. 각 표본 내부의20일+정답1일은 항상 연속입니다.

종로구 예시는 학습 정답2021-03-12~2023-08-21(730개), 검증2023-08-22~10-20(60개), 테스트2023-10-21~12-19(60개), 재생2023-12-20~2024-03-18(90개)입니다. 구별 정확한 범위는 representatives.json의partitions와 evidence/frozen-data-manifest.json에 있습니다.

정규화 scaler는 학습 표본의 입력·정답에 사용한 관측만 보고 맞춥니다. 검증·테스트·시연 값으로 scaler의 최소·최대값을 다시 맞추지 않습니다. 이전20일 문맥을 쓰므로 분할 경계에서 입력 날짜 일부가 앞 구간과 겹칠 수 있지만 정답 날짜는 겹치지 않습니다. 검증은 학습 중 모델 선택·초기 게이트, 테스트는 잠근 평가, 재생은 배포 후 날짜별 정답 도착을 재현하는 역할입니다.

### 5. 모델·저장소·API·화면을 어떻게 엮었는가

구별 고정 관측소마다 독립 모델25개를 관리합니다. 잔차 LSTM은 마지막 수위에 학습한 변화량을 더해 다음 날 수위를 구하고, scaler 역변환 후 원단위gl.-m로 응답합니다. 직전 수위를 그대로 쓰는 persistence와 오차를 비교합니다. 수위가 거의 변하지 않는 구간에서는 이 단순 기준도 강하므로 LSTM이 항상 더 좋다고 가정하지 않습니다.

```text
공개 관측소 HTML → 날짜·수위·강수 추출 → 공식 CSV + 고정 manifest
  → 기본: 원관측 보존 + 오늘까지 합성 확장 / 과거 검증: 원관측 전용
  → 연속20일 입력/다음날 정답 → 시간순 분할 → 학습·scaler·초기 평가
  → MLflow 모델·champion + SQLite 작업·예측·이벤트
  → FastAPI가 선택 namespace의 실제 모델로 예측 → 화면에 값·버전·입력 종료일·예측일 표시
  → 과거 검증에서 하루 진행 → 이전 예측 정답 대조 → 21일 RMSE → 경보·후보 재학습
  → 후속30일 같은 입력 비교 → 게이트 통과 시 교체 / 실패·정답 부족 시 기존 유지
```

CSV는 관측값, manifest는 관측소·단위·매핑·분할, SQLite는 작업·세션·예측·정답·이벤트, MLflow는 모델·지표·버전을 담당합니다. 같은 데이터인지CSV SHA-256으로, 같은 매핑인지mapping_version으로 구분합니다. 예측은 namespace·구 코드·모델 버전·예측일·자료ID를 함께 식별합니다. 새 시연 세션은 별도UUID namespace이므로 기본 과거 모델이나 합성 실험의 이력을 덮어쓰지 않습니다.

GET /api/v1/forecasts?replay_id=...는 원자료as_of까지의 마지막20일만 사용합니다. 표시용simulation 객체의 날짜는 모델 입력이 아닙니다. POST /replays/{id}/advance에days=1을 보내면 worker가 t+1 정답을 공개하고 오차·필요시 재학습을 처리합니다. 화면 상세에서 다음 날 예측점의 관측·강수는 정답 공개 전null입니다. 이때 예측값과 실제값이 둘 다 있어야 RMSE를 계산할 수 있으므로 첫날부터21일 감시 결과가 있는 것으로 표시하지 않습니다.

### 6. 실제 자료와 모의 실험의 구분

공급 시뮬레이션은 공식 관측값을 바꾸지 않고 공급 시점만 재현합니다. 수위 변화 재생은 특정 날짜 이후 값에+0.2를 더하는 별도 모의 시나리오입니다. 자동 승격 성공 검증은 별도 합성AR(1)+추세 자료이며 서울 실측 향상 성능이 아닙니다. 현재 강수 기록이0인 구간도 많아 원자료 강수 품질과 모델의 강수 효과를 독립 검증한 것으로 주장하지 않습니다.

### 드리프트 시연 선택 표시 보완

운영 화면에서 현재 선택한 기본 상황 또는 드리프트 시연을 초록색 ‘선택됨’ 버튼과 시연 ID로 확인합니다. 드리프트가 기본으로 선택되는 것은 아니며, 기존 검증 기록을 선택하면 그 상황이 복원됩니다. 같은 선택 버튼을 다시 눌러도 시연을 초기화하지 않습니다. 새로 시작하는 동작은 ‘선택한 상황으로 처음부터’로 분리했습니다. 1일·21일·남은 자료 끝까지 진행은 선택한 시연을 이어갑니다.

새 시연의 기본 변화는 첫 정답의 22일째부터 +0.2이며 원본을 바꾸지 않습니다. 이미 생성된 시연의 설정은 보존합니다. 드리프트는 21일 RMSE의 반복 초과 경보이며 물리적 원인을 확정하지 않습니다. 자료 입력 종료·후보 평가·모델 교체는 다른 상태이고, 후속 정답 부족은 평가 미완료로 표시합니다. 실제 90일 결과와 설정 변경 검증 범위는 evidence/README.md의 해당 날짜 기록을 따릅니다.
