# 팀 사용·로직 안내

## 대상 사용자와 범위

업무 담당자는 관측소별 입력 날짜·다음 날 예측·최근 수위와 강수를 확인합니다. 서비스 운영자는 자료·모델 준비, 오차 경보, 재학습과 교체·복귀를 확인합니다. 발표자는 같은 화면에서 저장 자료를 순서대로 공개해 운영 흐름을 설명합니다. 공공기관 직접 구매는 B2G이며 과제 B2B 조건 인정 여부는 아직 확인 사항입니다.

기본 자료에는 합성 구간이 있습니다. 학습과 예측·품질 감시는 실제 코드로 실행하지만 최신 실제 서울 관측값이나 현장 안전 판단을 제공한다는 뜻은 아닙니다. 교수자의 시뮬레이션 사용 허용은 사용자 전달 근거입니다.

## 화면 사용 순서

1. **관측소 현황**에서 예측 준비 수와 입력 기준일·예측 대상일을 확인합니다. 입력 기준일은 사용한 마지막 자료 날짜, 예측 대상일은 결과가 해당하는 날짜입니다.
2. **상세 보기**에서 예측 카드와 최근 수위·강수 그래프를 확인합니다. 기본 30일이며 90·180일로 변경할 수 있습니다. 내일의 수위·강수 정답은 아직 없으므로 예측점만 표시합니다.
3. **모델 관리 · 시연**에서 ‘기본 상황 선택’ 또는 ‘드리프트 시연 선택’을 누르고 모델 준비를 기다립니다. 선택된 상황을 다시 누르면 진행을 초기화하지 않습니다.
4. ‘저장 자료 1일 진행’·‘저장 자료 21일 진행’·‘남은 자료 끝까지 진행’으로 날짜별 정답을 공개합니다. 로딩·완료 일수·감지·재학습·후속 평가를 확인합니다. 새로 시작하려면 ‘선택한 상황으로 처음부터’를 누릅니다.
5. ‘오늘 예측으로 돌아가기’는 조회 복귀입니다. ‘이전 모델 복귀’는 이전 검증 모델을 사용하는 별도 작업이며 사유 입력 없이 요청합니다.

최근 입력 숫자와 그래프 해당 점은 같은 날짜의 저장 예측보다 높으면 빨강·↑, 낮으면 파랑·↓입니다. 소수 셋째 자리까지 같거나 저장 예측이 없으면 기본 색입니다. 다음 날 예측은 주황을 유지합니다. 이는 단일 날짜 차이이며 안전 등급이나 드리프트 경보가 아닙니다.

‘관리자용 · 자료 등록과 학습’은 다른 자료로 실험할 때만 사용합니다. CSV와 관측소·단위 JSON을 등록하고 검증 완료 뒤 학습 작업을 요청합니다. 기본 조회 자료가 바뀔 수 있으므로 일반 조회·기본 시연의 필수 절차로 사용하지 않습니다.

## 채택한 React 화면

사용자와 팀의 선택에 따라 기존 `team-test/frontend`의 React·TypeScript·Vite 화면을 정식 `team/frontend`로 채택했습니다. 데이터·모델·감지·재학습 정책은 기존 team 구현을 유지하며, React 정적 화면 제공에 필요한 main.py 라우팅과 Docker 빌드만 추가했습니다. API는 같은 서버의 기존 /api/v1을 사용하고 루트에서 /dashboard/로 이동합니다. /legacy/에는 기존 HTML·JS 화면을 보존합니다.

현황의 3D 서울 구 경계는 선택을 위한 고정 높이 지도이며 높이·위치는 수위·위험 순위가 아닙니다. 통계 구 코드와 API 구 코드는 같지 않아 검증된 구 이름으로 연결합니다. 실제 관측소 위치를 추정하지 않습니다. 경계 원문과 라이선스는 frontend/public/geo에 있습니다. 상세 지하 단면은 signed 수위 표시 개념도이며 실제 지질·지하수 흐름 모사가 아닙니다. 예측 미준비·null은 가짜 숫자로 채우지 않습니다. WebGL 사용이 어려우면 2D 목록과 차트, 3D 끄기를 사용할 수 있습니다.

Jotai는 조회·관측소 선택 상태를 관리하고 Three.js 장면은 별도 lazy chunk입니다. 접속 때 8단계 사용 가이드가 열리며 닫기·건너뛰기·Escape·다시 열기를 제공합니다. 안내는 학습·재생·자료 진행을 자동 실행하지 않습니다. 일반 API는 30초, 운영 상태는 3초마다 조회합니다. 끝까지 진행은 화면이 열린 동안 21일 단위 요청을 순차 접수하고 중지는 다음 접수만 막습니다. 이미 접수한 작업은 서버에서 계속됩니다.

이전 team-test 폴더와 8102 중복 컨테이너는 정리했습니다. 원본 소스·자료·Git 이력은 과제 루트 archive/team-test-before-removal-2026-10-08.zip에 보존했습니다.

원래 React 디자인에 최근 MVP 보완도 연결했습니다. 선택 관측소의 실제 관측 종료·입력 종료·합성 기간·생성 시각, 수집 활성·매핑·입력·모델·발행 상태, 실제 시연 변화 날짜·양을 서버 응답으로 표시합니다. 자료 수집과 기본 예측 반영을 구분합니다.

## 데이터가 화면까지 오는 과정

```text
서울시 공개 관측자료 HTML
→ 날짜별 수위·강수 정규화 + 고정 25개 관측소 명세
→ 원본 보존 + 별도 합성 확장 자료
→ 연속 20일 입력 / 다음 날 정답 / 시간순 분할
→ 구별 LSTM·scaler 학습과 품질 게이트
→ 저장 모델로 다음 날 예측 → API → 화면
→ 시연에서 정답 공개 → 오차 감시 → 재학습·후보 평가
```

수위와 강수는 같은 서울시 관측 HTML의 날짜 인덱스로 연결했습니다. 기상청 ASOS를 현재 기본 CSV에 결합한 것이 아닙니다. 관측은 `station_id + date`, 구·관측소·단위는 고정 manifest로 연결합니다. 결측 강수를 0으로 채우거나 날짜 공백을 이어 붙이지 않습니다. 원천·기간·생성식은 [데이터 설명](../data/README.md)이 기준입니다.

모델 입력은 수위·강수 2개 변수의 연속 20일이며 다음 날 수위 하나를 계산합니다. 마지막 입력 수위에 LSTM이 학습한 변화량을 더하는 residual 구조입니다. 구별 모델과 scaler를 독립 관리하며 scaler는 학습 구간만 사용합니다. 학습·검증·테스트·운영 재생을 시간순으로 나눕니다. 설정과 게이트는 [운영 기준](operations.md)에 있습니다.

기본 기동에서 오늘까지 합성 자료를 생성·검증·학습합니다. 같은 날짜 재기동은 저장 자료·모델을 재사용합니다. 날짜가 바뀐 자료 생성은 재기동 시 실행하며 자정 자동 갱신을 구현한 것은 아닙니다. 외부 API는 별도 진단·수집 경로이고 기본 화면의 공급원이 아닙니다.

## 교수님 원본과 달라진 점

| 구분 | 제공 HAIC 스켈레톤 | 현재 GroundWatch |
| --- | --- | --- |
| 대상 | 가격 시계열 학습 예제 | 관측소별 지하수위 |
| 입력 | Date·Close·Volume | 날짜·수위·강수·관측소·단위 |
| 모델 | 예제 예측 모델 | 구별 residual LSTM·train-only scaler |
| 감지 | 가격 예제 임계값 | 검증 기반 rolling RMSE 정책 |
| 기록 | 예제의 메모리 중심 흐름 | SQLite 작업·예측·이벤트와 MLflow 모델 |
| 후보 처리 | 실습 흐름 | 후속 정답 평가 후 교체·기존 유지·복귀 |
| 화면 | 실습 API 중심 | 현황·상세·모델 관리 및 시연 |

기반은 사용자 제공 `project.zip`의 학습용 HAIC 스켈레톤입니다. 보존한 HAIC 파일의 가격 임계값·41행 실습 성능을 지하수 성능으로 설명하지 않습니다. 원본 위치는 과제 루트의 `individual/practice/project/`이며 팀 코드와 구분합니다. 팀 역할 배정과 각자의 직접 작성 성과도 구분합니다.

## 발표에서 설명할 순서

한형준이 20분 이내로 문제와 사용자 → 자료 연결 → 예측 화면 → 드리프트 시연 → 평가 결과와 한계 → 팀 역할 순서로 설명합니다. 교수자 안내대로 기획서 순서에 맞춘 실제 화면 스냅샷을 사용합니다. ‘작업 접수’, ‘후보 생성’, ‘평가 통과’, ‘실제 새 모델 예측’은 서로 다른 상태입니다. 최신 증거와 이전 실행 결과는 [실행 증거](../evidence/README.md)에서 구분합니다.
