# 팀 사용·로직 안내

## 대상 사용자와 범위

업무 담당자는 관측소별 입력 날짜·다음 날 예측·최근 수위와 강수를 확인합니다. 서비스 운영자는 자료·모델 준비, 오차 경보, 재학습과 교체·복귀를 확인합니다. 발표자는 같은 화면에서 저장 자료를 순서대로 공개해 운영 흐름을 설명합니다. 제안 고객은 지하수 관측·시설 유지관리 업무를 수행하는 기업의 운영 담당자와 서비스 운영자입니다(B2B). 공공기관은 자료 제공·업무 협업 대상이며, 실제 고객 계약이나 도입 효과를 검증한 것은 아닙니다.

기본 기획은 서울25개 구별 대표 관측소 관제입니다. 기본 자료 범위 라벨은 ‘서울25개 구별 대표 관측소’이며 내부 식별자 `seoul-history`는 과거 자료만 별도 제공한다는 제품 의미가 아닙니다. 현재 조회·종로구(11110) 선택으로 시작합니다. 서울 추가 실측22,582행을2026-09-30까지 확보했습니다. 10월1일 이후 합성 확장은 실측과 구분하며, 입력이 오래되면 `STALE`·미준비를 표시합니다. 추가 실측 조회를 기존 모델 재평가·승격 완료로 설명하지 않습니다. 합성 입력·재학습 시연은 실측과 구분합니다.

전국 광주도척·무안무안·제주조천3곳의280일 실측은 자료 범위에서 선택하는 추가 확장 옵션입니다. 원천 계약·실제 수위·관측 가용성이 확인된 지점만 추가 제공하며 기본 서울 자료의 최신성을 대신하지 않습니다. 위치 원천 목록1,048개는 확보 카탈로그 수이고 모든 지점의 실측·모델 제공을 뜻하지 않습니다.

## 화면 사용 순서

1. 기본 ‘서울25개 구별 대표 관측소’에서 현재 조회·종로구 선택 상태를 확인합니다. 오늘 기준으로 서울 입력이 오래되면 미준비 상태를 그대로 확인합니다.
2. 서울3D 구 경계 지도에서 구를 선택하고 상세의 GL 개념 단면·수위·강수·장마 정보와 모델 관리를 확인합니다.
3. ‘저장 자료 검증’을 선택하면 확보된 날짜의25개 관측소별 모델 준비 상태를 확인합니다. 최종 현재 입력에서는23개가 준비됐고2개는 미준비입니다. 합성 시연에서는 기본 상황·드리프트와 저장 자료 진행을 사용하며 실제 관측 결과로 설명하지 않습니다.
4. 전국 추가 실측 범위를 선택하면3곳의 실제 수위·강수·해발 수위 비교도·모델 상태를 조회합니다. D−1→D 값은D일11:30 이후 발행하는 당일 추정이며 LSTM 미준비 지점의 persistence는 비교값입니다.
5. 전국 실제 강수 지도와3곳 장마 성능 비교는 추가 자료 범위에서 유지합니다. 미연결 예보·특보·원천 진단 패널은 제외합니다. 기존21일 감지·41일 재학습·30일 후보 평가와 운영 승격 정책은 변경하지 않습니다.

최근 입력 숫자와 그래프 해당 점은 같은 날짜의 저장 예측보다 높으면 빨강·↑, 낮으면 파랑·↓입니다. 소수 셋째 자리까지 같거나 저장 예측이 없으면 기본 색입니다. 다음 날 예측은 주황을 유지합니다. 이는 단일 날짜 차이이며 안전 등급이나 드리프트 경보가 아닙니다.

‘관리자용 · 자료 등록과 학습’은 다른 자료로 실험할 때만 사용합니다. CSV와 관측소·단위 JSON을 등록하고 검증 완료 뒤 학습 작업을 요청합니다. 기본 조회 자료가 바뀔 수 있으므로 일반 조회·기본 시연의 필수 절차로 사용하지 않습니다.

## 채택한 React 화면

사용자와 팀의 선택에 따라 기존 `team-test/frontend`의 React·TypeScript·Vite 화면을 정식 `team/frontend`로 채택했습니다. 데이터·모델·감지·재학습 정책은 기존 team 구현을 유지하며, React 정적 화면 제공에 필요한 main.py 라우팅과 Docker 빌드만 추가했습니다. API는 같은 서버의 전국 통합 /api/v2와 서울 /api/v1을 자료 범위에 맞게 사용하고 루트에서 /dashboard/로 이동합니다. /legacy/에는 기존 HTML·JS 화면을 보존합니다.

기본 현황 지도는 서울3D 구 경계이며 구를 선택해 대표 관측소 상세로 연결합니다. 전국 추가 자료 범위에서는 확보 실측 관측소의 위치와 실제 강수 레이어를 표시합니다. 전국 관측소 상세는 원천 해발 수위 기준의 Three.js 수위 비교도이며 지표 높이를 가정하지 않습니다. 최근 실측과 추정 또는 persistence 비교값을 값·날짜·라벨로 구분합니다. 서울 과거 자료 범위의 GL 수위는 지표0m를 기준으로 한3D 개념 단면을 유지합니다. 실제 지층·관정 시공 도면은 확보하지 않았으므로 지층 두께·관정 깊이·실제 공간 분포를 표시하지 않습니다. 예측 미준비·null은 가짜 숫자로 채우지 않습니다. 3D 해제·WebGL 미지원·오류에서는 같은 원천값의2D 비교도를 제공합니다.

Jotai는 조회·관측소 선택 상태를 관리하고 Three.js 장면은 별도 lazy chunk입니다. 접속 때 8단계 사용 가이드가 열리며 닫기·건너뛰기·Escape·다시 열기를 제공합니다. 안내는 학습·재생·자료 진행을 자동 실행하지 않습니다. 일반 API는 30초, 운영 상태는 3초마다 조회합니다. 끝까지 진행은 화면이 열린 동안 21일 단위 요청을 순차 접수하고 중지는 다음 접수만 막습니다. 이미 접수한 작업은 서버에서 계속됩니다.

이전 team-test 폴더와 8102 중복 컨테이너는 정리했습니다. 원본 소스·자료·Git 이력은 과제 루트 archive/team-test-before-removal-2026-10-08.zip에 보존했습니다.

원래 React 디자인에 최근 MVP 보완도 연결했습니다. 선택 관측소의 실제 관측 종료·입력 종료·합성 기간·생성 시각, 수집 활성·매핑·입력·모델·발행 상태, 실제 시연 변화 날짜·양을 서버 응답으로 표시합니다. 자료 수집과 기본 예측 반영을 구분합니다.

## 서울 자료 범위의 데이터 흐름

```text
서울시 공개 관측자료 HTML
→ 날짜별 수위·강수 정규화 + 고정 25개 관측소 명세
→ 원본 보존 + 별도 합성 확장 자료
→ 연속 20일 입력 / 다음 날 정답 / 시간순 분할
→ 구별 LSTM·scaler 학습과 품질 게이트
→ 저장 모델로 다음 날 예측 → API → 화면
→ 시연에서 정답 공개 → 오차 감시 → 재학습·후보 평가
```

수위와 강수는 같은 서울시 관측 HTML의 날짜 인덱스로 연결했습니다. 기상청 ASOS를 현재 기본 CSV에 결합한 것이 아닙니다. 관측은 `station_id + date`, 구·관측소·단위는 고정 manifest로 연결합니다. 결측 강수를 0으로 채우거나 날짜 공백을 이어 붙이지 않습니다. 원천·기간·생성식은 [데이터 설명](../data/README.md)이 기준입니다.

모델 입력은 수위·강수 2개 변수의 연속 20일이며 다음 날 수위 하나를 계산합니다. 마지막 입력 수위에 LSTM이 학습한 변화량을 더하는 residual 구조입니다. 구별 모델과 scaler를 독립 관리하며 scaler는 학습 구간만 사용합니다. 학습·검증·테스트·운영 재생을 시간순으로 나눕니다. 설정과 게이트는 [운영 기준](operations.md)에 있습니다.

서울 합성 확장 설정이 활성화된 기동에서는 오늘까지 합성 자료를 생성·검증·학습합니다. 같은 날짜 재기동은 저장 자료·모델을 재사용합니다. 날짜가 바뀐 자료 생성은 재기동 시 실행하며 자정 자동 갱신을 구현한 것은 아닙니다. 이 문단은 서울 합성 자료 범위의 동작입니다. 추가 전국3곳은 공식 GIMS·기상청 실측 결합을 사용하며 합성 서울 자료와 분리합니다.

## 전국 확장·장마 대응 초기 설계 검토 이력

아래 설계의 전체 관측소 목록·미연결 예보·특보 화면 제안은 현행 제공 범위가 아닙니다. 현재 사용자 화면은 서울25개 구 기본 관제·전국 실측3곳·별도 합성17개 시나리오를 제공합니다. 확보 원본과 검토 이력은 보존하지만 위치만 있는 지점을 기본 관제로 확대하지 않습니다.

현재 구현 방향은 **기존 지하수 관제 서비스의 단일 현황·상세·모델 관리 흐름을 전국으로 확장**하는 것입니다. 전국 강수·실측 샘플을 별도 서비스로 제공하던 첫 화면은 통합 대상으로 전환합니다. 관측소를 선택하면 해당 수위·연결된 강수·장마 평가·예측·드리프트·후보 상태가 같은 선택을 유지합니다. 서울 시연과 기존 모델 이력은 호환 어댑터로 보존합니다.

자료 원천·단위 계약 확인(`source_contract_verified`)과 강수 연결 상태(`mapping_status`), 운영 승인(`operational_approved`)을 구분합니다. 원천·시각·단위·품질이 검증되고 근거·버전이 기록된 실험 매핑은 실측 학습·평가에 사용할 수 있지만 운영 승인으로 표시하지 않습니다. 실험 예측에는 그 상태를 명시하고, 운영 승인 없는 후보의 승격은 차단합니다. 단일 관측소 원천 수위 학습에 전국 공통 기준면의 전기간 이력 검증을 일괄 요구하지 않으며, 확인된 원천 기준을 그대로 보존하고 다른 기준으로 변환하지 않습니다.


2026-10-08 사용자 요청 당시의 단계별 설계 기록입니다. 현재 구현 범위는 아래 통합 구현·검증 항목과 실행 증거를 따릅니다. 이 설계에는 미구현 후속 제안도 포함하며 서울25개 관측소 계약과 운영 정책의 변경 승인 기록이 아닙니다. API·DB·모델 입력의 공통 계약 변경안은 웹·데이터 담당자 합의 후 contracts.md에 확정합니다. 작업 브랜치는 `feat/aiops/geonwoo/model-promotion-policy`이며 main 병합은 요청 범위에 없습니다.

### 목표와 범위

전국의 검증된 관측소에서 다음 날 지하수위를 예측하고, 장마·강한 강수 구간의 성능을 따로 평가합니다. 관측소가 없는 지역의 수위를 생성하거나 관측소 하나를 시군구 전체의 대표값으로 단정하지 않습니다. 전국 자료 수집과 장마 대응은 단계별 기능으로 출시하며 자료가 충분한 관측소부터 활성화합니다. 싱크홀 발생 확률 예측은 포함하지 않습니다.

현재 `data/groundwater.py`는 서울 구 코드와 구당 대표 관측소 1개를 검증하고, `observation_repository.py`의 매핑도 구별 유일성을 가집니다. `live_observations.py`는 서울 수위 원천과 전체 25개를 전제로 합니다. `groundwater_models.py`의 입력은 `(20, 2)`이며 후보 평가도 같은 입력을 전제합니다. 전국 확대는 원천 URL 교체만으로 완료되지 않습니다.

최근접 기상 관측소는 연결 후보로 제시하고 거리만으로 자동 승인하지 않습니다. 강수·예보·특보는 각각 관측소 ID·격자·특보구역으로 별도 매핑합니다. 결측을 0으로 바꾸거나 날짜 공백을 연결하지 않습니다. 지표 기준 수심과 해발 기준 수위를 혼합하지 않으며 변환 근거가 없으면 원래 기준별로 관리합니다.

기존 SQLite와 모델 파일은 보존합니다. 전국용 새 테이블·namespace와 명시적 schema migration을 도입하고 기존 구별 UNIQUE를 전역 삭제하지 않습니다. 구별 기존 API는 서울 호환 경로로 유지하고 새 전국 API는 관측소별로 제공합니다. 기존 모델을 전국 모델로 재표시하지 않습니다.

### 일별 수집·예측·정답 처리

서버 KST 기준의 설정 가능한 일별 실행시각을 사용합니다. 초기 제안은 11:30이며 지하수 자료 발행 지연을 조사한 뒤 확정합니다. ASOS 전일 자료의 공개 시각만으로 지하수 준비를 가정하지 않습니다. 기존 one-step 모델의 대상일은 반드시 `input_end_date + 1일`입니다. D일 11:30에 D-1일까지 확정 자료를 사용하면 대상은 D일이며, 이를 달력상 내일 D+1 예측이라고 표시하지 않습니다. 이 운영은 대상일이 이미 시작된 당일 일수위 추정입니다. 진정한 내일 예측은 D까지 일자료가 완료된 뒤 발행하거나, D-1까지 자료로 D+1을 학습하는 별도 horizon=2 모델이 필요합니다. 1차 전국 M0/M1/M2는 기존 horizon=1을 유지하고 `target_date`, `input_end_date`, `issued_at`, `horizon_days`, `forecast_timing`으로 의미를 표시합니다. horizon 변경은 별도 모델·시간 분할·승격 평가 범위이며 41일/30일 정책을 그대로 적용하지 않습니다.

원본 수집 → 품질·단위 검증 → 날짜 결합 → 불변 snapshot 생성 → 호환 모델 확인 → 예측 저장 순으로 실행합니다. 완전한 일강수와 진행 중 당일 누적강수를 구분합니다. 예보는 정보 마감시각 이전에 발표되고 실제 수집된 최신 발표본만 사용합니다. 같은 예측 키의 재시도는 중복 발행하지 않습니다.

이후 대상일의 수위 정답이 도착하면 당시 저장된 예측과 비교합니다. 정답 수정은 revision과 재평가 이력을 남기며 이미 확정된 승격 근거를 조용히 덮어쓰지 않습니다. 공급자 실패·부분 수집·오래된 자료는 자료 상태이고 모델 드리프트와 별개입니다. 재기동 뒤 놓친 날짜를 재처리하되, 당시 정보가 없는 과거 예측을 실제 발행 예측으로 만들지 않습니다.

### 모델 실험 순서

| 단계 | 입력·목적 | 출시 조건 |
| --- | --- | --- |
| M0 | 기존 20일 수위·일강수 구조를 관측소별 재학습 | 전국 실측 baseline 확보, persistence와 시간 분리 평가 |
| M1 | 20×2 시계열 + 입력 마지막 시점의 별도 요약벡터(3/7/14일 누적 강수·연속 강수일수 최대20일·대상일 연중 날짜 sin/cos) | 기존 대비 전체·장마·강한 강수 평가. 각 timestep의 추가 과거 문맥을 요구하지 않아 41일 자료 유지 가능 |
| M2 | M1 + 예측 대상일 강수 예보를 별도 요약벡터로 결합 | 과거 발표본 확보·시각 누수 검증·공통 날짜 비교 통과 |

시간 최대강수량은 별도 입력 계약의 후속 실험으로 둡니다. 예보 강수량이 구간/문자열이면 정확한 수치인 것처럼 합산하지 않고 하한·상한·범주·결측 상태를 보존하는 전처리를 설계합니다. 강수확률을 강수량으로 대체하지 않습니다. M2는 예보 수집 실패 시 결측을 0으로 채우지 않고 별도 검증된 관측 전용 모델을 사용할 수 있으며, 사용 모델과 대체 사유를 기록합니다. 입력 계약을 달리하는 모델의 결과는 감지 창에서 섞지 않습니다.

장마 시작·종료일은 우선 사후 성능 분석에만 사용합니다. 사후 확정된 날짜를 당시 알고 있었던 실시간 입력처럼 쓰지 않습니다. M1/M2는 기존 모델과 입력 수가 달라 기존 가중치를 그대로 복제하는 파인튜닝 대신 새 초기 학습을 수행합니다. 동일 입력 계약 내 파인튜닝에는 기존 41일 정책을 적용할 수 있습니다. 예보 입력 모델은 41일의 수위만으로 충분하지 않으며 해당 날짜에 실제 이용 가능했던 예보 snapshot도 필요합니다.

### 장마·강한 강수 평가와 승격

먼저 기존 모델이 장마에 더 부정확한지 측정합니다. 관측소별 전체·장마·비장마·강한 강수 구간의 RMSE·MAE·표본 수와 연도별 결과를 기록합니다. 장마 라벨 매핑이 불명확한 관측소는 미분류로 남깁니다. 강한 강수는 초기 제안으로 학습 구간 일강수 P95 이상이며 임계값을 평가 전에 고정합니다. 이 분석 구분은 기상청 호우특보 기준과 다릅니다.

시간순 분할과 train-only scaler를 유지하고, 가능한 경우 여러 해 장마를 포함한 순차 검증을 수행합니다. 평가할 미래 연도는 특징·정책 선택에 쓰지 않습니다. 장마 표본 확보를 위해 현재 730개 학습 정답 상한을 늘릴지는 자료 조사 후 별도 비교하며, 전 지역에 자료가 충분하다고 가정하지 않습니다.

전국 M0는 현 초기 게이트(검증 RMSE ≤ persistence × 1.10)를 계승하되 persistence보다 우수하다는 주장과 구분합니다. M1/M2는 같은 관측소·수위 정답·단위·공통 평가 날짜에서 각자의 입력 계약으로 예측을 생성해 비교합니다. 예보가 없는 날짜를 후보만 제외하여 유리한 표본으로 비교하지 않습니다. 전체 날짜 대비 예보 확보율과 모델별 사용 가능률도 보고합니다.

기존 30일 후속 RMSE 5% 개선·과거 guard 악화 10% 이내 게이트는 유지합니다. 다음은 장마 대응 모델의 추가 출시 게이트 제안이며 합의·구현 전에는 적용 중이라고 설명하지 않습니다.

- 동결된 별도 계절 검증에서 장마 RMSE가 비교 모델보다 5% 이상 감소하고 비장마 RMSE 악화가 10% 이내일 것.
- 강한 강수 구간 RMSE 악화가 10% 이내일 것. 각 핵심 구간 정답 최소 30개를 초기 운영 기준으로 제안하며 부족하면 통과가 아니라 `insufficient_seasonal_evidence`로 대기할 것.
- 계절 검증과 guard는 후보 학습에 사용하지 않은 날짜로 보존할 것. 파인튜닝 데이터가 보존 구간과 겹치면 다음 검증 구간을 확보하기 전 자동 승격하지 않을 것.
- 30일 후속 평가에 장마가 없어도 사전 계절 검증이 충족되면 전체 게이트와 함께 판단할 수 있으나, 최근 장마 개선을 입증한 것으로 설명하지 않을 것.
- 비교 모델 변경, 입력 계약 불일치, 비유한 지표, 정답 누수, 로딩·시험 예측 실패는 승격 차단. 계약이 다른 비교는 계약별 예측기를 호출하며 기존 단일 입력 비교 함수를 그대로 재사용하지 않을 것.

추가 수치와 최소 표본은 최적값이 입증된 것이 아니라 보수적인 출시 기준 제안입니다. 기존 서울 후보에는 소급 적용하지 않습니다. 승격 시 모델·scaler·입력 계약을 하나의 묶음으로 전환하고 실패·복귀 때도 같은 묶음으로 되돌립니다. 21일 감지와 21일 cooldown을 먼저 변경하지 않으며 전국 관측소별로 임계값을 산출합니다.

### 화면·API 변경안과 단계별 완료 기준

병렬 설계 검토로 확인한 구현 선행 조건은 다음과 같습니다.

- K-water/AWS/예보 수집기는 서울 전용 분기를 재사용하지 않고 공급자별 어댑터로 구현합니다. 과거 대량 수집에는 기간 분할·페이지 체크포인트·호출 제한·실패 후 재개를 둡니다. 부분 성공은 관측소별로 기록합니다.
- 원천 시각은 `provider_published_at`(확인될 때만), `first_seen_at`, `collected_at`, `availability_evidence`를 구분합니다. 오늘 내려받은 과거 파일의 수집시각으로 당시 자료 가용성을 입증하지 않습니다. 역사적 예보 발표본 기반 재현과 당시 실제 발행 기록은 별도 평가 모드입니다.
- 같은 장소의 암반·충적 관측정, 관측소 이전·기준면 변경은 독립 관측정/시계열 구간으로 식별합니다. 단위가 m로 같다는 이유로 연결하지 않습니다. 공급자별 무강수·결측 코드, 일 경계·일평균 정의를 확정하고 기록합니다.
- M1의 연속 강수일수는 입력 20일 안에서 센 최대20 값이며 무제한 연속일수와 다릅니다. 요약벡터 scaler도 학습 자료만 사용합니다. 예보 입력용 과거 발표본이 없으면 M2 평가·승격을 보류하고 M0/M1까지만 구현합니다.
- 동일 계약 파인튜닝은 관측정·단위/기준면·입력 순서/차원·horizon·전처리·강수 매핑의 불변성을 학습 전에 검사합니다. metadata 덮어쓰기로 기존 모델을 새 계약에 맞는 것으로 재표시하지 않습니다.
- 현재 후보 비교는 fine_tune 종류와 2특징 입력을 전제하므로 새 초기 학습 후보도 평가 가능한 후보 유형과 계약별 입력 adapter를 추가합니다. 동결 evaluation manifest에 후보/기존 버전, 원천 revision, 공통 날짜, 입력 계약별 snapshot, 가용률, 정책 버전을 보존합니다.
- 기존 guard는 early stopping에 사용한 검증 구간이며 독립 최종 평가와 구분합니다. 전국 장마 출시에는 train / tuning-validation / acceptance-holdout을 분리합니다. holdout 정답은 파인튜닝에도 쓰지 않으며, 과거 입력 문맥의 중첩은 허용하되 보존 정답의 학습 사용은 차단합니다.
- 계약 변경 후보의 historical guard 기준은 동결된 같은 날짜에서 기존 모델을 재평가한 RMSE × 1.10으로 정의합니다. 후보 자신의 검증 RMSE를 기준으로 삼지 않습니다. 기존 서울 동일 계약 후보의 초기 검증 기준은 변경하지 않습니다.
- 전국 UI는 기존 district 선택 상태·서울 GeoJSON·v1 접두사와 분리한 station 선택 상태 및 API client를 사용합니다. 준비 수·모델·이벤트·작업·rollback 키도 모두 관측소와 namespace로 격리하고, 동일 지역 복수 관측소의 독립 동작을 검증합니다.
- 전국 scheduler/worker 동시 실행에는 `(namespace, station_id)`별 DB lease와 활성 generation을 둡니다. 현재 프로세스 내부 RLock만으로 다중 프로세스 승격을 보호하지 않습니다. 평가 시작·전환 직전에 비교 모델·매핑·계약 generation을 확인하고, DB의 단일 활성 묶음 참조를 기준으로 캐시·Registry를 복구합니다.
- 같은 계절 holdout으로 반복 후보를 선택해 과적합하지 않도록 최종 연도 보류 구간을 별도로 남깁니다. 후보의 학습 부모와 현재 비교 champion을 별도 필드로 기록합니다.
- v2 목록은 `items,next_cursor,total`과 필터 범위 전체의 준비 집계를 반환합니다. 예측 응답은 단위·기준면·입력/대상/발행 날짜·horizon·모델/매핑/계약/snapshot 버전·상태를 포함합니다. ID의 URL/파일/모델명 인코딩 규칙, 미존재404·형식422·준비부족503, 학습·작업 조회·복귀 API를 공통 계약 합의에 포함합니다.
- 초기 전국 화면은 지역 검색·목록과 확인된 좌표의 점 지도로 구현합니다. 좌표가 없는 관측소도 목록에서 조회할 수 있고 단위·기준면이 다른 절대수위를 같은 색상 척도로 비교하지 않습니다.

### 추가 확보한 기상 자료와 자동 갱신

지상·AWS 완료 일강수는 2026-10-07 기준 723개 지점의 값과 원천 좌표를 확보했습니다. ASOS 일자료와 중복 합산하지 않습니다. AWS 분자료는 원천 확보 이력으로 보존하며 기본 사용자 화면의 별도 진단 패널은 제외합니다. API허브 단기예보 신청과 실제 정상 응답도 확인했으나, 공식 예시 격자 55/127을 실제 지역에 연결하지 않았으므로 전국 예보로 설명하지 않습니다. 특보 조회의 0행 응답은 의미 검증 전이며 ‘특보 없음’이나 안전 상태가 아닙니다.

별도 weather worker는 `GROUNDWATCH_WEATHER_COLLECTION_ENABLED=true`일 때 AWS 분자료를 10분 간격, 완료 일강수를 11:30 이후 전일 기준으로 수집합니다. 기본 Compose에서는 true이며, 모듈을 직접 실행하고 환경변수를 생략하면 false입니다. 수집 실패 시 마지막 정상 파일을 유지하고 수집 상태 API에 실패를 기록합니다. 이 수집기는 지하수 관측소 승인이나 모델 학습을 자동으로 수행하지 않습니다. 전국 실측3곳의 원천 계약·명시적 기상 매핑과 자료 가용성을 확인했으며 운영 승인은 별도로 유지합니다.

전국 지상·AWS 일강수 이력은 2026-01-01~10-07의 연속 280일, 201,206관측을 확보하여 날짜 선택·3D 지도·지점 이력에 연결했습니다. 날짜별 제원과 이름을 보존하며, 조회일에 원천에 없는 지점을 해당 날짜 지도에 임의 배치하지 않습니다. gzip 이력과 runtime 최신 완료일을 합칠 때 동일 날짜는 마지막 정상 수집 자료로 갱신하고 과거 날짜는 유지합니다. 대표 지하수의 강수 후보는 과거 최대 연속 구간과 최신 연속 구간을 구분합니다. 용인549·제주가시리890은 최신 구간 길이가 충분하지만 무안699는 최신 구간이 41일이므로 현재 초기 학습 길이 기준을 충족하지 않습니다. 이 세 AWS 지점은 대안 후보입니다. 현행 실험 모델은 공식 제원명과 일치하는 이천203·목포165·성산188의 각280일을 연결하며 원천 계약 확인과 운영 승인을 구분합니다.

기존 관측소 상세 화면에서는 확보한 관측소의 수위·강수 이력을 조회합니다. 추가 전국3곳의 상세·모델 관리는 단일 관제 흐름으로 제공합니다. 원천의 el.m/m 표기를 유지하며, 기준점 이력·강수 연결 승인·모델 준비 상태를 함께 표시합니다. GIMS 위치 원천1,023개는 기본 화면에서 제외하며 모든 지점의 수위가 확보됐다는 의미가 아닙니다. 원본은 삭제하지 않습니다.

### 수위 비교도와 실제 도면의 구분

전국 3곳의 해발 수위는 지표 높이를 가정하지 않는 Three.js 수위 비교도로 표시합니다. 실측과 추정/비교값을 청록·금색 면으로 구분하고 드래그 회전·스크롤 확대를 제공합니다. 3D 보기 해제 또는 WebGL 미지원/오류 시에만 같은 값의 2D 비교도를 표시합니다. 실측·추정 또는 persistence의 값·날짜·원천 기준을 구분하며 선택 관측소에 따라 갱신됩니다. 서울 GL 기준은 기존 3D 개념 단면을 유지합니다. 실제 지층·관정 시공 도면은 확보하지 않았으므로 그림에서 지층 두께·관정 깊이·실제 지하수 분포를 읽을 수 없습니다. 최근 30·90·180일 차트는 각각 최대 해당 개수의 저장 관측값을 표시하며 결측값은 생성하지 않습니다.

서울 상세의 공식 장마 기간은 서울(108) 통계를 사후 평가 참고로 연결합니다. 기존 서울 원천 강수 입력을 ASOS108로 교체하지 않으며, 해당 통계는 실시간 장마 판정이나 미래 예보가 아닙니다.

수위·연결 강수 차트의 금색 배경은 선택 구간과 겹치는 공식 장마 기간(사후 평가용)입니다. 다른 참고 기상지점 강수에는 지하수 관측소의 장마 라벨을 임의 적용하지 않습니다.

## 후속 적용 범위와 현재 상태

아래 항목은 원래 후속 설계의 범위입니다. 현재 서울 추가 실측 확보·기존 화면 통합·합성17개 시나리오·M0/M1 다년 평가·후보 만료·재기동 검증까지 구현했습니다. 실제 전국 승인·관정 도면 확보·전향적 실측30일 승격은 남은 과제입니다. 서울25개 구 기본·단일 관측소 선택 흐름을 유지합니다.

1. 서울 최신 자료: 공식 수집 응답에서 날짜·관측소ID·GL기준·단위·결측을 확인하고 기존 대표 manifest와 연결합니다. 연결 실패는 STALE로 남기며 임의 대체 관측소나 합성값으로 최신성을 만들지 않습니다. 실제 최신 연속20일 입력과 다음날 정답 수집을 완료 기준으로 둡니다.
2. 전국 확대: 전체 카탈로그를 지역별 수집 후보로 조회하고 관측 기간·결측·기준면·좌표 이력을 점검합니다. 같은 시군구의 여러 관측소를 허용하되 서울 구대표 정책은 유지합니다. 관측소와 ASOS/AWS의 거리·고도·동시 보유기간을 근거로 명시적 매핑을 검토합니다. 자료 준비·실험 모델 준비·운영 승인 상태를 분리하고 검증을 통과한 관측소만 기존 지도·상세·모델 관리에 추가합니다.
3. 장마 개선: 여러 해 자료를 먼저 확보하고3/7/14일 누적 강수·수위 반응 지연·계절 특징의 추가 효과를 비교합니다. M0·강수 보강M1·persistence를 같은 정답 날짜로 평가하고 train/validation/acceptance holdout을 시간순으로 분리합니다. 확정 장마 통계는 사후 평가용이며 미래 입력에 넣지 않습니다. 전체·장마·비장마·강한 강수 RMSE/MAE·표본수를 기록하고 기존30일5%개선/guard10% 정책을 유지합니다. 계절 표본이 부족하거나 개선 실패면 후보를 운영 승격하지 않습니다.
4. 실제 단면 자료: 공식 지질·시추·관정 제원을 조사하고 좌표·관정ID·출처·이용조건·지표고·층경계·조사일을 검증합니다. 같은 관정의 도면만 실제 관정 단면으로 표시하고 주변 시추는 거리와 별개 자료임을 명시합니다. 미확보 시 기존 개념도를 유지합니다. 해발·GL 기준 변환은 확인된 지표고가 있을 때만 수행합니다.
5. 운영 후속 평가: 기존 모델과 후보 예측을 대상일 이전에 함께 발행·저장하고 이후 실제 정답과 연결합니다. 새 정답30일이 지나야 승격 판단할 수 있으며 과거 재현30일로 대체하지 않습니다. 중복 발행·재기동·수집 실패·늦은 정답에서도 상태와 원래 판단 근거를 보존합니다.

적용 순서는 최신·장기 원천 확보 → 관측소/강수/도면 매핑 검토 → 모델 비교 → 기존 화면 통합 → 실제 HTTP·브라우저·재기동 검증 → 발표자료 동기화입니다. API·자료 형식 변경은 영향과 예시를 contracts.md에 제안하고 팀 합의 전 확정하지 않습니다. 개인 브랜치에서 진행하며 main병합·공유배포는 별도 요청입니다.

### 시뮬레이션 보완 적용 (개발 검증)

자료가 부족한 기능을 끝까지 검증하기 위해 합성 자료 사용을 허용한 사용자 지시에 따라 다음을 적용합니다. 실제 원천 결측은 그대로 보존하며, 합성값을 실제 관측 API 응답이나 운영 성능으로 표시하지 않습니다.

- 서울25개 고정 대표: 동결 원본과 검증된 추가 실측(2026-09-30까지)을 합성 시연 데이터셋에 함께 보존하고, 2026-10-01 이후에만 합성 꼬리를 생성합니다. 원본 파일과 실제 모델 공간은 변경하지 않습니다. 합성 자료가 포함된 전체 데이터셋은 별도 synthetic 모델 공간에서 학습합니다.
- 전국17개 시·도: 후보 위치를 참고한 합성 수위·강수 시나리오를 2022년부터 전날까지 생성합니다. 지역별1개 시나리오이며 실제 지역 대표 수위가 아닙니다. 상대 기준면을 사용하고 실제 해발 높이로 변환하지 않습니다. 실제3개 관측소 옵션과 같은 지도·상세·모델관리 흐름에서 별도 자료 범위로 선택합니다.
- 합성 원천: 고정seed20261008, 연간계절성·강수반응·잡음과2026-07-10 이후0.45m 변화 시나리오입니다. 6/20~7/25 장마 창은 시나리오 분류이며 공식 장마 통계가 아닙니다. 시뮬레이션 가용시각과 실제 생성시각을 구분합니다.
- M0/M1 비교: 2022~2023 학습, 2024년1~3월 tuning-validation, 2024년4월~2025년12월 acceptance-holdout으로 시간 분리합니다. 두 모델과 persistence를 동일 정답으로 비교하고 전체·장마·비장마·강한 강수 표본수와 RMSE/MAE를 보존합니다. 합성 장마는 매년6/20~7/25 시나리오이며 640일 holdout 중72일, 비장마568일입니다. 공식 장마 확정 통계와 별도로 분류합니다. 실패 결과도 표시합니다.
- 후보 종료: 동결된 M1 acceptance 구간에 필수 계절표본30개가 없으면 시간이 지나도 그 구간의 표본이 늘지 않으므로 `expired_insufficient_seasonal_evidence`로 종료합니다. 나머지 후보가 후속 정답·발행 근거를 확보하지 못하면 기본90일 뒤 `expired_shadow_timeout`으로 종료하고 기존 모델을 유지합니다. 새로운 후보를 만들 때도 원래 승격 조건은 유지합니다.

Compose의 `GROUNDWATCH_NATIONAL_SIMULATION_ENABLED=true`가 전국 시나리오를 준비하고 학습 작업을 등록합니다. `false`이면 새 합성 준비를 실행하지 않습니다. 이미 볼륨에 저장된 합성 이력은 원본과 별도로 보존됩니다. `GROUNDWATCH_CURRENT_EXTENSION=true`는 서울 합성 확장을 준비합니다. 합성 모델은 운영 승인 상태로 전환하지 않으며, 빠르게 재생한30일은 실제 앞으로30일을 운영한 증거가 아닙니다. 실제 관정 도면을 확보하지 못한 부분은 상대 수위 비교도·개념도로 남기며 관정 깊이·지층 두께를 실제로 주장하지 않습니다.

학습 worker는 공통 파일 잠금으로 TensorFlow 작업을 직렬화하며 작업마다 새 프로세스를 사용합니다. 작업 중단 이력은 `interrupted`로 보존하고 자동으로 다시 학습하지 않습니다. 실패·중단 작업의 재요청은 작업 API에서 명시적으로 수행합니다. 합성 다년 비교는 `GROUNDWATCH_SYNTHETIC_SEASONAL_EVALUATION_ENABLED=true`일 때 일반 학습 큐가 비면 실행하며, 모델별 하위 프로세스와 결과 캐시를 사용합니다.

API허브 ASOS 일자료 활용 승인과 실제 응답을 확인했습니다. 2020~2025년3지점 자료는 유효2,731행·결측3,845행이며 원천 음수 결측을0으로 채우지 않았습니다. 원천 확보를 연속6년 모델 입력이나 전국 실측 완비로 설명하지 않습니다. 원천·교차 대조는 [데이터 기준](../data/README.md)을 따릅니다. 이번 구현은 Python226개 통과·1skip, 프런트30개 통과와 production build를 확인했습니다. 전국 합성17개 시나리오의 M0·M1 총34개 다년 평가도 완료했습니다. 전체 pooled RMSE는0.04083→0.04066m로 소폭 감소했지만5%개선 관측소는0곳이며 장마·강한 강수 pooled RMSE는 악화됐습니다. 장마 정확도 개선이나 실측 운영 승격 성과로 설명하지 않습니다.
