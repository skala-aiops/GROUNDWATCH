# 팀 사용·로직 안내

## 대상 사용자와 범위

업무 담당자는 관측소별 입력 날짜·다음 날 예측·최근 수위와 강수를 확인합니다. 서비스 운영자는 자료·모델 준비, 오차 경보, 재학습과 교체·복귀를 확인합니다. 발표자는 같은 화면에서 저장 자료를 순서대로 공개해 운영 흐름을 설명합니다. 공공기관 직접 구매는 B2G이며 과제 B2B 조건 인정 여부는 아직 확인 사항입니다.

기본 화면은 서울시 지하수·기상청 강수 API 관측으로 학습한 별도 모델을 사용합니다. 공급자 지연이 있으므로 최신 가용 관측일과 예측 대상일을 확인해야 합니다. 공식 과거 CSV·합성 확장은 별도 시연 자료이며 교수자의 시뮬레이션 사용 허용은 사용자 전달 근거입니다. 모델 품질과 현장 안전 판단은 구분합니다.

## 화면 사용 순서

1. **관측소 현황**에서 예측 준비 수와 입력 기준일·예측 대상일을 확인합니다. 입력 기준일은 사용한 마지막 자료 날짜, 예측 대상일은 결과가 해당하는 날짜입니다.
2. **상세 보기**에서 원관측·같은 날짜 강수·시험 구간 예측·최신 입력 다음 날 예측을 확인합니다. 기본 30일이며 90·180일로 변경할 수 있습니다. 아직 수신하지 못한 예측 대상일의 수위·강수 정답은 null입니다.
3. 실제 API 모드의 **모델 관리 · 시연**에서 관측소별 7단계와 대기 이유를 확인합니다. ‘실제 API 자료 다시 수집’은 원천을 다시 호출하고, ‘새 정답·드리프트 확인’은 저장된 자료로 평가합니다. ‘미준비 모델 학습 다시 시도’는 기존 모델을 재사용하며 미준비 관측소를 다시 처리합니다.
4. 경보·후보 평가·작업 실패를 확인합니다. 새 정답이 없으면 감시·재학습·평가는 대기합니다. 작업 실패는 원인을 확인하고 재시도합니다. ‘이전 검증 API 모델로 복귀’는 복귀 가능한 이전 승격 모델이 있을 때만 활성화됩니다.
5. 시연할 때만 조회 모드를 **과제 시연 예측**으로 바꾸고 ‘기본 상황 선택’ 또는 ‘드리프트 시연 선택’을 누릅니다. 모델 준비 뒤 ‘저장 자료 1일 진행’·‘저장 자료 21일 진행’·‘남은 자료 끝까지 진행’으로 날짜별 정답을 공개합니다. 같은 상황 선택은 초기화하지 않으며 ‘선택한 상황으로 처음부터’가 새 세션을 만듭니다. 시연의 자료 진행은 실제 API 수집에 영향을 주지 않습니다.

최근 입력 숫자와 그래프 해당 점은 같은 날짜의 저장 예측보다 높으면 빨강·↑, 낮으면 파랑·↓입니다. 소수 셋째 자리까지 같거나 저장 예측이 없으면 기본 색입니다. 다음 날 예측은 주황을 유지합니다. 이는 단일 날짜 차이이며 안전 등급이나 드리프트 경보가 아닙니다.

‘관리자용 · 자료 등록과 학습’은 다른 자료로 실험할 때만 사용합니다. CSV와 관측소·단위 JSON을 등록하고 검증 완료 뒤 학습 작업을 요청합니다. 기본 조회 자료가 바뀔 수 있으므로 일반 조회·기본 시연의 필수 절차로 사용하지 않습니다.

## 실제 API 관측 경로

기본 조회 모드는 `실제 API 관측·예측`입니다. ApiObservationFeed가 서울시 전체 응답에서 최신 유효 관측 기준 365일을 최대 120페이지까지 검증해 고정 관측소 이름의 원값을 추출합니다. 기상청 ASOS 108 강수는 코드에서 날짜별 결합하며 CSV에 추가해 기존 모델을 다시 쓰는 방식이 아닙니다. ASOS 108은 서울 공통 참고 지점이며 각 관측정의 현장 강수계가 아닙니다.

수위는 물리적 기준을 미확정으로 남긴 `API 원값`입니다. 강수 빈값은 null로 보존하며 별도 모델의 입력에서만 학습 구간 중앙값과 결측 표시로 처리합니다. 수위·강수·결측 표시 3개 특성의 모델을 `api_native_masked_v1`에서 학습합니다. 기존 gl.-m·2개 특성 모델과 섞지 않습니다. 과거 “종로구 연속 수위·강수 완전 관측 최대 10일” 진단은 이 결측 처리 모델의 입력 부족을 뜻하지 않습니다.

GET `/api/v1/api-observations`는 관측·예측·준비 수, `/{code}/history`는 차트, `/{code}/pipeline`은 실제 운영 상태를 제공합니다. 조회는 저장 결과를 읽으며 매번 외부 API를 호출하지 않습니다. 자동 수집은 KST 10시 이후 하루 1회 배치이고 실패 시 1시간 후 재시도합니다. 60초 점검·화면 3초 조회와 외부 호출 주기를 혼동하지 않습니다. 실패하면 직전 성공 자료와 오류를 함께 보존합니다.

실제 예측 발행 당시 없던 정답이 이후 수집돼야 오차가 누적됩니다. 연속 21일 RMSE의 연속 2회 초과 후 41일 자료로 후보를 학습하고, 후보 이후 30일 정답에서 5% 개선·과거 guard 110% 이내를 모두 통과해야 교체합니다. 시험 구간 예측은 이 감시에 넣지 않습니다. 전체 정책은 [운영 기준](operations.md)을 따릅니다.

## 채택한 React 화면

사용자와 팀의 선택에 따라 기존 `team-test/frontend`의 React·TypeScript·Vite 화면을 정식 `team/frontend`로 채택했습니다. 채택 당시 기존 비즈니스 로직을 유지했고, 이후 실제 API 모델·운영 경로를 별도로 추가해 기본 모드에 연결했습니다. API는 같은 서버의 /api/v1을 사용하고 루트에서 /dashboard/로 이동합니다. /legacy/에는 기존 HTML·JS 화면을 보존합니다.

현황의 3D 서울 구 경계는 선택을 위한 고정 높이 지도이며 높이·위치는 수위·위험 순위가 아닙니다. 통계 구 코드와 API 구 코드는 같지 않아 검증된 구 이름으로 연결합니다. 실제 관측소 위치를 추정하지 않습니다. 경계 원문과 라이선스는 frontend/public/geo에 있습니다. 상세 지하 단면은 signed 수위 표시 개념도이며 실제 지질·지하수 흐름 모사가 아닙니다. 예측 미준비·null은 가짜 숫자로 채우지 않습니다. WebGL 사용이 어려우면 2D 목록과 차트, 3D 끄기를 사용할 수 있습니다.

Jotai는 조회·관측소 선택 상태를 관리하고 Three.js 장면은 별도 lazy chunk입니다. 접속 때 8단계 사용 가이드가 열리며 닫기·건너뛰기·Escape·다시 열기를 제공합니다. 안내는 학습·재생·자료 진행을 자동 실행하지 않습니다. 일반 API는 30초, 운영 상태는 3초마다 조회합니다. 끝까지 진행은 화면이 열린 동안 21일 단위 요청을 순차 접수하고 중지는 다음 접수만 막습니다. 이미 접수한 작업은 서버에서 계속됩니다.

이전 team-test 폴더와 8102 중복 컨테이너는 정리했습니다. 원본 소스·자료·Git 이력은 과제 루트 archive/team-test-before-removal-2026-10-08.zip에 보존했습니다.

원래 React 디자인에 최근 MVP 보완도 연결했습니다. 선택 관측소의 실제 관측 종료·입력 종료·합성 기간·생성 시각, 수집 활성·매핑·입력·모델·발행 상태, 실제 시연 변화 날짜·양을 서버 응답으로 표시합니다. 자료 수집과 기본 예측 반영을 구분합니다.

## 데이터가 화면까지 오는 과정

```text
서울시 VTsSec 원수위 + 기상청 ASOS 서울 108 강수
→ 코드에서 날짜별 결합 → 원본·해시별 스냅샷 보존
→ 연속 20일 수위 / 강수 중앙값·결측 표시 / 실제 다음 날 정답
→ 시간순 분할·train-only 전처리·구별 별도 LSTM·초기 게이트
→ 최신 가용 관측 다음 날 예측 발행 → API → 화면
→ 이후 수집된 정답 → 오차 감시 → 재학습 → 30일 평가 → 교체/유지
```

실제 API 자료는 원본 CSV를 덮어쓰지 않고 `runtime/groundwatch/external/feed/`에 저장합니다. 관측소·날짜·입력 해시·모델 버전으로 출처를 추적합니다. 원천·기간·시연 생성식은 [데이터 설명](../data/README.md)이 기준입니다.

별도 CSV·시연은 같은 서울시 공개 HTML의 날짜 인덱스로 묶은 수위·강수 2개 특성을 사용합니다. 원자료의 마지막 실측 이후를 별도 합성 확장하며 실제 API 원값 모델과 학습·평가를 분리합니다. 두 모델 모두 마지막 수위에 LSTM 변화량을 더하는 residual 구조이며 구별 scaler는 학습 구간만 사용합니다.

기동 시 시연용 자료도 준비하며 같은 날짜 재기동은 자료·모델을 재사용합니다. 합성 확장 날짜 변경은 재기동 시 실행하는 경로이고, 기본 실제 API 수집은 외부 worker의 별도 일정으로 실행합니다.

| 구분 | 제공 HAIC 스켈레톤 | 현재 GroundWatch |
| --- | --- | --- |
| 대상 | 가격 시계열 학습 예제 | 관측소별 지하수위 |
| 입력 | Date·Close·Volume | 날짜·수위·강수·관측소·단위 |
| 모델 | 예제 예측 모델 | 구별 residual LSTM·train-only scaler |
| 감지 | 가격 예제 임계값 | 검증 기반 rolling RMSE 정책 |
| 기록 | 예제의 메모리 중심 흐름 | SQLite 작업·예측·이벤트와 MLflow 모델 |
| 후보 처리 | 실습 흐름 | 후속 정답 평가 후 교체·기존 유지·복귀 |

기반은 사용자 제공 `project.zip`의 학습용 HAIC 스켈레톤입니다. 보존한 HAIC 파일의 가격 임계값·41행 실습 성능을 지하수 성능으로 설명하지 않습니다. 원본 위치는 과제 루트의 `individual/practice/project/`이며 팀 코드와 구분합니다. 팀 역할 배정과 각자의 직접 작성 성과도 구분합니다.

## 발표에서 설명할 순서

한형준이 20분 이내로 문제와 사용자 → 자료 연결 → 예측 화면 → 드리프트 시연 → 평가 결과와 한계 → 팀 역할 순서로 설명합니다. 교수자 안내대로 기획서 순서에 맞춘 실제 화면 스냅샷을 사용합니다. ‘작업 접수’, ‘후보 생성’, ‘평가 통과’, ‘실제 새 모델 예측’은 서로 다른 상태입니다. 최신 증거와 이전 실행 결과는 [실행 증거](../evidence/README.md)에서 구분합니다.
