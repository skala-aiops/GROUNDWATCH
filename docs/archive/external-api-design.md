# 외부 관측 API 연결 설계 초안

이 문서는 최초 조사 초안으로 보존합니다. 키 저장·활용승인·수집 및 관측DB/live 경로는 이후 구현했으며 최신 기준은 [전면 재설계](2026-10-08-before-cleanup/api-transition-redesign.md)·[계약](../contracts.md)·evidence/api-source-readiness.json입니다. 아래 미구현 설명을 현재 상태로 읽지 않습니다.

조사일: 2026-10-07. 구현 전 설계이며 인증키를 사용한 호출, 최신 관측일, 25개 관측소 매칭은 아직 확인하지 않았습니다. 기존 코드와 데이터는 변경하지 않았습니다.

## 목적과 판단

운영 담당자가 CSV를 매번 준비하는 작업을 줄이고 관측자료 갱신 실패와 지연을 확인하도록 서버 수집 작업을 추가합니다. 서울시 일별 수위와 기상청 일강수량을 결합하되 실제 최신성·단위·관측소 일치가 확인된 자료만 예측에 사용합니다. 싱크홀 확률이나 현장 안전 판단을 제공하는 설계가 아닙니다.

## 공식 조사 결과

- 서울시 자료: https://data.seoul.go.kr/dataList/OA-15611/A/1/datasetView.do
- 서울시 상세 명세: https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-15611&srvType=A
- 서비스명 `VTsSec`. 공식 예시는 `http://openapi.seoul.go.kr:8088/(인증키)/xml/VTsSec/1/5/영등포구-당산공원/2018`입니다. JSON도 지원합니다. 인증키, 시작·종료 위치가 필요하며 관측소 이름 `OBSVTR_NM`, 관측일 `OBSRVN_YMD`가 선택 인자입니다. 명세의 날짜 형식은 yyyymmdd인데 예시는 연도만 사용하므로 날짜 필터의 동작을 실제 요청으로 확인해야 합니다. 요청당 최대 1,000건, sample 키는 최대 5건입니다.
- 주요 출력은 `OBSVTR_NM`, `OBSRVN_YMD`, `UDGD_WATL`입니다. 상세 출력 명세에서 수위 단위·기준면을 확인하지 못했습니다. 기존 물순환정보 페이지의 gl.-m와 같은 의미라고 확정하지 않습니다. 공식 예시가 HTTP이므로 HTTPS 지원 여부를 검증한 후 인증키 전송 경로를 결정합니다.
- 키 없는 sample JSON 호출에서 INFO-000, 총 879,379건과 5행을 확인했으며 5행 모두 날짜가 20410130이었습니다. 실제로 반환된 값이며 날짜 오타의 원인은 미확인입니다. 쿼리 문자열로 이름·날짜를 추가한 시험은 같은 5행을 반환해 필터 동작의 증거로 사용하지 않습니다. 공식 경로 인자 방식으로 후속 검증합니다.
- 기상청 공식 명세: https://www.data.go.kr/data/15059093/openapi.do
- 요청주소 `https://apis.data.go.kr/1360000/AsosDalyInfoService/getWthrDataList`. `ServiceKey`, `dataCd=ASOS`, `dateCd=DAY`, `startDt`, `endDt`, `stnIds`를 사용하고 `dataType=JSON`, `pageNo`, `numOfRows`를 지정합니다. 종료일은 전일(D-1)까지 제공한다고 명시되어 있습니다. `tm`, `stnId`, `sumRn`을 사용하고 9-9강수 `n99Rn`과 혼동하지 않습니다. `sumRn`은 선택 필드이므로 누락을 처리해야 합니다.
- 기상청은 무료·개발/운영 자동승인, 개발계정 트래픽 10,000으로 안내합니다. 실제 적용 한도와 이용 기간은 발급 계정에서 다시 확인합니다.
- ASOS는 주요 도시의 종관관측망이며 더 촘촘한 관측이 필요하면 AWS를 검토할 수 있습니다. 이번 초안은 ASOS를 사용하며 AWS 혼합은 별도 계약 변경입니다. https://data.kma.go.kr/data/grnd/selectAsosRltmList.do?pgmNo=36&tabNo=2

## 수집 흐름

```text
서울시 VTsSec ── 수위 원본 ──┐
                            ├→ 원본 보존 → 정규화·격리 → 날짜·고정 매핑 결합
기상청 ASOS ── 강수 원본 ────┘                              ↓
                                           버전별 CSV+manifest 검증
                                                          ↓
                                 준비된 자료 활성화 → 예측·정답·오차 감시
                                                          ↓
                                           기존 게이트 기반 재학습
```

브라우저는 외부 API를 직접 호출하지 않습니다. 화면은 저장된 자료와 수집 상태를 우리 API로 조회합니다. CSV 업로드와 과거 재생은 유지합니다. 초기에는 수동 수집 작업 하나로 검증하고 이후 별도 수집 프로세스가 정기 작업을 접수합니다. 학습 worker를 기다리느라 수집이 멈추지 않도록 네트워크 수집과 TensorFlow 작업 실행을 분리합니다. Kafka나 새 서비스는 추가하지 않습니다.

## 관측소와 데이터 계약

기존 25개 고정 관측소 ID를 유지하고 서울시 API의 정확한 이름과 연결합니다. 이름만으로 동일 관측소를 확정하지 않고 공식 코드·위치·원본 기간 중첩을 대조합니다. 중복 이름, 이전·개명, 불일치는 수집 대상에서 격리하며 자동 교체하지 않습니다.

새 매핑 버전에는 내부 station_id, 서울시 API 이름, 검증된 단위·기준면, 기상청 관측소 코드·좌표·거리·선정 이유·유효기간을 기록합니다. 기상청 108은 공식 예시 코드이며 25개 구에 일괄 적용한다고 확정하지 않습니다. 지하수 관측소별로 이용 가능한 ASOS의 거리와 자료 기간을 비교해 고정하고 공유 관측소는 한 번만 수집합니다.

정규 CSV의 기존 필수 6개 열은 유지합니다. rain_source, weather_station_id, collection_id, mapping_version, 단위 확인 근거와 원본 해시는 manifest 및 출처 메타데이터로 보존합니다. 수집 시각과 관측 날짜를 구분합니다.

미래 날짜·잘못된 날짜·비수치·음의 강수·단위 불명·충돌은 격리합니다. 수위 음수는 부호만으로 오류 처리하지 않으며 절댓값 변환하지 않습니다. 명시적인 강수 0은 유지하고 누락/공백은 0으로 만들지 않습니다. 무강수 공백의 공식 의미가 추가 확인되면 근거를 기록한 별도 정책 버전으로 적용합니다. 결측 날짜를 보간하거나 다른 날짜와 연결하지 않습니다.

## 수집과 실패 정책 제안

- 시간대 Asia/Seoul. 매일 10:00 전일까지 수집하는 것을 초기 운영 설정으로 제안합니다. 공식 갱신 보장 시간이 아니며 실제 지연을 측정해 조정합니다.
- 최초에는 선택 관측소의 짧은 기간으로 필드와 날짜 필터를 확인하고, 이후 학습 기간 전체를 나눠 수집합니다. 매일 최근 7일을 재조회해 지연 입력·정정을 찾고 장기 공백은 별도 backfill 작업으로 복구합니다. 7일보다 늦은 정정은 운영 기록을 보고 재조회 범위를 조정합니다.
- 소스·관측소·조회 범위별 수집 작업을 중복 방지하고 모든 페이지를 완료했는지 확인합니다. 빈 데이터, 부분 수집, HTTP 성공 안의 오류 코드를 구분합니다.
- 일시적 timeout·5xx에는 제한된 지수 backoff와 jitter를 사용합니다. 인증 실패는 자동 반복하지 않고 운영 알림, 한도 초과는 공급자 안내까지 대기합니다. 호출 한도는 계정별 설정으로 관리합니다.
- 관측값을 조용히 덮어쓰지 않고 원본 응답 해시와 수집 시각별 수정 이력을 남깁니다. 새 스냅샷 검증 후 활성 포인터를 원자적으로 교체합니다. 수집 실패는 마지막 검증 자료를 유지하고 최신성 상태를 별도로 표시합니다.
- 비밀키는 서버 환경변수만 사용합니다. URL 경로/쿼리의 키도 로그·오류·작업 응답에서 마스킹합니다. 원본 응답과 비밀값을 제거한 요청 조건을 보존합니다. HTTP 전용인 경우 키 노출 위험을 해결하기 전 자동 운영을 시작하지 않습니다.

## 현재 코드에서 반드시 분리할 버전

`groundwater_models.py`의 check_ready는 station_id, level_unit, mapping_version뿐 아니라 dataset_version의 완전 일치를 요구합니다. 수집 스냅샷이 바뀌면 기존 모델이 준비 실패할 수 있어 업로드 API만 반복 호출해서는 연결이 끝나지 않습니다.

모델의 training_dataset_version은 고정하고 inference_dataset_version은 입력 스냅샷으로 별도 기록합니다. 모델 적용 가능 여부는 관측소·단위·입력 열 순서·특성 정책·매핑 버전·학습 시간 경계로 검증합니다. 단순 행 추가는 모델 재학습을 강제하지 않고, 출처·단위·강수 관측소·전처리 변경은 재학습과 게이트 통과가 필요합니다. 캐시·예측 이력·readiness에도 같은 규칙을 적용합니다.

현재 강수는 서울시 물순환정보 관측 페이지 제공 값이며 기상청 관측소 코드가 확인되지 않았습니다. 기상청 강수로 변경하면 특성 출처가 달라집니다. 기존 모델에 새 강수를 즉시 주입하지 않고 같은 ASOS 자료로 과거 학습·검증·테스트 입력을 다시 만들고 persistence 및 기존 방식과 비교합니다. 새 모델은 별도 namespace 예: observed_api_v1로 관리합니다. 현재 queue_upload가 실측을 historical로 고정하는 부분과 latest_dataset의 최신 ready 선택도 출처별 활성 데이터 선택으로 보완해야 합니다. 과거 재생과 수집 자료를 자동 혼합하지 않습니다.

## 예측과 운영 화면

입력이 기준일 D까지 연속 20일 준비되면 D+1 수위를 예측합니다. 당일에 전일까지 두 자료가 준비되면 당일 수위 예측을 제공할 수 있습니다. 자료가 며칠 지연되면 과거 예측일을 오늘 예측처럼 표시하지 않습니다. 기상청 일자료만으로 당일까지 입력한 내일 예측을 보장하지 않습니다.

current에서 오늘 예측은 전일까지 연속 입력과 모델 호환성·최신성이 확인된 관측소에만 제공합니다. 전체 25개 조회는 행마다 관측일·예측일·준비 사유를 표시하며 준비 개수만 집계합니다. 동일 기준일 비교는 그 날짜를 만족한 관측소만 대상으로 합니다. 마지막 원천 관측일, 마지막 수집 성공 시각, 데이터 지연, 수집 오류, 모델 품질 경보를 분리합니다. 수집 장애를 모델 성능 저하로 해석하지 않습니다.

정답이 실제 도착한 뒤에만 예측 오차를 계산합니다. 원천 정정 시 영향받은 지표를 새 버전으로 재계산하되 같은 날짜의 경보·재학습을 중복 생성하지 않습니다. 기존 21일 RMSE와 후보의 후속 30일 평가를 유지하며 데이터 수집 자체는 재학습 성공이나 모델 교체를 뜻하지 않습니다.

## 내부 API 추가안

아래는 아직 합의·구현되지 않은 제안입니다. 기존 API는 유지합니다.

- POST /api/v1/ingestions: from_date, to_date, 선택 district_codes를 받아 수집 작업 202와 job_id를 반환합니다. 외부 URL이나 키를 요청으로 받지 않습니다. 공개 서비스에서는 인증·운영자 권한 적용 후 노출합니다.
- GET /api/v1/ingestions/{id}: 소스별 상태·완료 페이지·수집/격리 행 수·실패 사유를 반환합니다.
- GET /api/v1/data-freshness: 관측소별 최종 관측일·마지막 성공 수집 시각·결합 상태를 반환합니다.

## 구현 순서와 완료 기준

1. 서울시 공식 경로 필터로 대표 관측소 하나의 실제 날짜 응답을 확인합니다. HTTPS, 단위·부호·동일 관측소, 실제 최신 관측일이 확인되어야 다음 단계로 갑니다. 미래 날짜가 포함되면 제외하고 유효 자료의 최신일을 별도로 조사합니다.
2. 같은 기간의 기상청 응답과 강수 결측 의미, 관측소 매핑을 확인합니다. 원본 30일과 정규화 결과를 대조하고 기존 강수와 차이를 보고합니다.
3. 두 소스 수집·원본 보존·페이지 처리·검증·중복 방지를 구현합니다. 정상/빈 응답/미래 날짜/키 오류/한도 초과/부분 실패/정정 자료/재시작 시험을 통과해야 합니다.
4. 학습 버전과 입력 자료 버전을 분리하고 별도 실측 API namespace로 과거 학습·평가합니다. 기존 재생 결과가 보존되고 미래 정답 누수가 없어야 합니다.
5. 25개 매핑·유효 기간을 확인한 뒤 정기 수집과 화면을 연결합니다. 실제 수집→스냅샷 검증→현재 예측→정답 도착→오차 기록을 확인해야 운영 연결 완료로 판단합니다.

현재 확정하지 못한 항목은 서울시 API의 실질적인 최신성·단위·HTTPS·필터 동작, 25곳 이름/코드 대응, ASOS 매핑, 인증키별 한도와 실제 수집 지연입니다. 이를 확인하기 전에는 실시간 연결 완료로 표시하지 않습니다.
