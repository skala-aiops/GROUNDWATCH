- Docker Engine 29.6.2, Linux ARM64 컨테이너, Python 3.11, TensorFlow 2.21.0, MLflow 3.16.0.
- 루트 Compose 구문 검사 통과. `docker compose up --build`와 동일한 설정을 `-d`로 기동해 빌드·초기화·healthy 상태 확인.
- 최초 학습 평가 RMSE 약 2.03으로 샘플 게이트 4 통과, Production v1 등록.
- `/health` 200, `model_loaded=true`. `/data/status` 200, 샘플 756행 확인.
- `/predict` 200: v1, 192.30 반환. 19일 입력과 음수 배치 입력은 각각 422.
- 마지막 41행 정상 배치: 예측 21개, `status=ok`.
- 동일 배치에 1000을 더한 변화 입력: 예측 21개, 재학습 실행, 평가 RMSE 1.470289596, v2 승격.
- 승격 직후 같은 예측 요청: v2, 193.31 반환. Registry 승격뿐 아니라 실제 서빙 응답 변경 확인.
- `/` 200과 Chrome에서 샘플 대시보드·업로드·배치 버튼·로그 목록 표시 확인. 버튼 전부의 UI 상호작용까지 검증한 것은 아님.
- `docker compose down` 뒤 `docker compose up --build -d`로 재기동: 추가 학습 없이 저장된 v2 사용, 같은 예측값 193.31 유지.
- 회귀 테스트 5개 통과: RMSE 경계·최소 윈도우, 입력 스케일과 lazy 캐시, 재학습 예외 시 기존 캐시 유지, 게이트 실패 시 캐시 유지, 승격 성공 시 캐시 갱신.
- Python 20파일 구문 및 실행 가능한 `___` 빈칸 부재 확인.

## 확인한 실패와 해결

- 제공 Dockerfile은 미구현 학습 스크립트를 빌드 중 실행하도록 되어 있었음. 빈칸을 구현하고 초기화는 컨테이너 최초 시작에서 수행하도록 분리.
- 기존 다른 컨테이너가 호스트 8099 포트를 사용해 첫 기동 실패. 기존 컨테이너를 멈추지 않고 팀 기본 포트를 8100으로 분리.
- Production 승격만으로 메모리 캐시가 교체되지 않는 구조를 확인해 성공 뒤 재로딩과 실제 버전 응답을 추가.

## 한계

재학습은 변화 요청 자체가 아니라 최신 CSV를 사용합니다. 따라서 위 결과는 파이프라인 연결 검증이며 변화 분포 적응이나 제품 성능 개선의 근거가 아닙니다. MLflow의 Production stage API는 현재 동작하지만 deprecated 경고가 있어 추후 alias 전환을 검토할 수 있습니다. CPU·패키지 환경에 따라 최초 학습 결과와 시간은 달라질 수 있습니다. AMD64 환경은 이번 세션에서 실행하지 않았습니다.
