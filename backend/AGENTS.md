# 백엔드·AIOps 작업 지침

저장소 공통 규칙은 [루트 AGENTS.md](../AGENTS.md)를 따릅니다. 작업 전에 [백엔드 README](README.md), [API 계약](../docs/contracts.md), [운영 기준](../docs/operations.md), [데이터 설명](../data/README.md)을 읽습니다.

## 변경 범위

- 라우터·서비스·저장소·모델·worker 역할과 Python 컨벤션은 README를 따릅니다. 공통 계약 변경은 루트 협업 절차를 따릅니다.
- 학습·서빙의 입력 순서·scaler·출력 복원·관측소·모델 버전이 일치하는지 확인합니다. 날짜 공백을 넘어 입력 창을 만들거나 미래 정답을 학습·평가에 섞지 않습니다.
- 드리프트는 관측된 예측 오차 신호입니다. 감지·알림·재학습 요청·후보 생성·게이트 판정·실제 서빙을 각각 확인합니다.
- 운영 정책은 operations.md를 기준으로 하며 문서에 맞추려고 임계값이나 성능 결과를 임의 변경하지 않습니다. 실패·정답 부족·평가 탈락 시 기존 모델 유지와 그 사유를 확인합니다.
- TensorFlow 작업의 공용 잠금·프로세스 격리, 중복 작업 방지와 재기동 복구를 보존합니다. 실제 관측 경로와 합성 시연 경로의 자료·모델·이력을 분리합니다.

## 완료 확인

- README의 잠금 명령으로 영향 테스트를 실행합니다. 서빙·승격 변경은 API 응답의 `model_version`과 예측 결과를 전후 비교합니다. Registry 기록만으로 실제 서빙 성공을 판단하지 않습니다.
- 정상·잘못된 입력·준비 부족·중복 요청·후보 탈락·작업 실패 중 변경과 관련된 분기를 확인합니다.
- 서비스 지표와 모델 품질을 따로 검증합니다. 짧은 p95·오류율 측정을 장기 가용성이나 SLA 달성으로 설명하지 않습니다.
- 실행 결과는 조건·자료 출처·실측/합성 여부와 함께 evidence의 현행 목록과 기록에 남깁니다. 실행하지 못한 항목은 operations의 추가 확인에 기록합니다.
- 모델·DB·원본 Secret·로컬 로그는 커밋하지 않습니다. 테스트에 실제 서비스 모델과 저장 상태를 사용해 변경하지 않습니다.
